\section*{Reproducibility Checklist}
\noindent\textbf{General paper structure.} Conceptual outline of the approach: yes (Figure~1 and the Approach section's stage specification). Claims vs.\ speculation delineated: yes (each RQ's answer box states only measured claims; the break-even expression in RQ2 is marked as derivation over measured quantities). Pedagogical references for background: yes (Related Work).

\smallskip
\noindent\textbf{Theoretical contributions.} This paper makes no formal theoretical claims; the break-even expression in RQ2 is elementary algebra over measured quantities, with all symbols defined in the text.

\smallskip
\noindent\textbf{Datasets.} All experiments use two publicly available corpora: the Refactory dataset \citep{refactory2019} and Codeforces problems and submissions from the open-r1 release \citep{penedo2025codeforces}. Our scripted import pipeline is released, covering test parsing, per-test entry points, and the oracle-fidelity audit, and we state the problem-selection rule we applied by hand, so the exact evaluation sets are reconstructible from the public corpora. No new human-subject data are collected.

\smallskip
\noindent\textbf{Computational experiments.} Source code, prompts, synthesized repairers, raw LLM responses, the ported Refactory-tool configuration, and analysis scripts are released; experiments run on CPU only. Model versions, pricing snapshot, tokenizer convention, decoding budget (single sample per call), execution timeouts, and the no-split whole-pool protocol are stated in Experimental Setup and fixed in the released configuration. Metrics are formally defined; repair rates carry 95\% Wilson intervals and every paired claim reports exact McNemar's $b$, $c$ and $p$. Local search and evaluation are deterministic, and the escalation threshold is a constant rather than a fitted quantity, so no configuration is selected on the evaluation set; the 29 alternatives we measured are reported in RQ5 rather than used to choose one. Tables, figures and every in-text number are generated from the released per-submission event logs by scripts in the artifact, so no reported value is transcribed by hand. Builder synthesis is stochastic; every round's prompt, response, and build-sample outcome for both builder tiers is released.
