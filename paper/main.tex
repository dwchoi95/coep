\begin{abstract}
Large language models (LLMs) repair buggy submissions to programming assignments well, but they are deployed \emph{one query per submission}: every request re-transmits the same assignment description and test suite, so cost grows linearly with enrollment and recurs every term, while caching and cheaper models shrink only the constant, not the structure.
Observing that assignment repair is a \emph{many-instances, one-specification} regime, we propose \textsc{CoEP}, a framework that shifts LLM investment from the submission to the assignment.
An LLM agent reads the specification, tests, and a few sample programs once, and synthesizes an executable symbolic repairer---problem-specific AST rewrite rules over a generic bounded edit search---whose every patch is independently test-validated and size-capped.
Refined through validation feedback and then deployed locally, the repairer fixes subsequent submissions at zero marginal LLM cost, escalating the rest to conventional per-submission repair so that coverage is never sacrificed; it is also a transparent artifact that instructors can audit, produces minimal patches by construction, and runs in milliseconds.
Experiments on real student programs, against per-submission LLM repair, a symbolic non-LLM tool, and cost-reduction alternatives such as caching and model cascades, show that amortizing LLM reasoning into a verifiable per-assignment artifact preserves repair quality while fundamentally improving the cost structure of serving many instances of one specification.
\end{abstract}

\section{Introduction}

Timely, individualized feedback is the scarcest resource in programming education.
Introductory courses routinely enroll hundreds of students on campus and tens of thousands online, each producing a stream of buggy submissions that instructors cannot examine one by one.
Automated program repair (APR) has therefore long been proposed as a feedback engine for programming assignments: given a buggy student submission and the assignment's test suite, produce a small patch that makes the submission correct while preserving the student's own approach \citep{itsp2017,clara2018,sarfgen2018,refactory2019,verifix2022}.

Large language models (LLMs) have made this vision practical.
LLM-based repair now fixes the large majority of real student programs---up to 96.5\% of buggy Python submissions in PyDex \citep{pydex2024}---and general-purpose LLM repair systems report strong results at modest per-bug prices \citep{chatrepair2024,alpharepair2022,fastfixer2024,cref2024}.
But these systems all share a deployment paradigm that we argue is mismatched with the economics of the classroom: \emph{every buggy submission triggers a fresh LLM query} that re-transmits the assignment description, the test suite, and formatting instructions before the model ever sees the student's code.
On the real student corpus we study, 79\% of the input tokens of a per-submission repair prompt are byte-identical across all submissions to the same assignment (\PrefixFrac\% in a contiguous cacheable prefix); the student's code is 21\% of what the course pays to process, query after query, semester after semester.
Provider-side prompt caching \citep{anthropiccaching,openaicaching} discounts the redundant prefix but does not change the paradigm: in our measurements it removes \CacheSavingFrac\% of the per-submission cost, and every submission still requires a round trip to a frontier model, with the attendant marginal cost, latency, rate limits, and dependence on an external service.

Our key observation is that assignment repair is a \emph{many-instances, one-specification} regime: a single assignment is attempted by hundreds of students whose failures cluster into recurring misconceptions \citep{clara2018,refactory2019}.
Pre-LLM systems exploited exactly this structure (CLARA clustered correct solutions; Refactory refactored them into a per-problem search space), achieving cheap per-submission repair at the cost of hand-built machinery or large pools of prior solutions; per-submission LLM repair inverts the trade-off, automatic and general but paying for the same specification-level reasoning on every query.

We propose to get both halves: \textbf{spend the LLM once per assignment, not once per submission}.
In \textsc{CoEP} (\underline{Co}st-\underline{E}ffective \underline{P}rogram repair), an LLM agent receives the assignment specification, test suite, a few reference solutions, and a handful of historical buggy submissions, and \emph{writes a program repairer}: a deterministic Python module combining problem-specific rewrite rules with a generic edit-search library, validating every candidate against the visible tests under a patch-size cap.
After at most three harness-driven refinement rounds it is frozen and deployed: submissions are repaired \emph{locally}, in milliseconds to seconds, at zero marginal LLM cost, and any the repairer cannot fix escalate to the conventional LLM path---so the hybrid never does worse than the paradigm it replaces.

On \NumProblems{} real assignments from the public Refactory dataset \citep{refactory2019}---1{,}685 buggy Python submissions written by university CS1 students---holding the underlying LLM fixed across all conditions, \textsc{CoEP}'s synthesized repairers alone fix \CoepRate\% of \NumEval{} held-out submissions at zero marginal LLM cost; with fallback, the hybrid fixes \HybridRate\% within the patch-size cap, \emph{exceeding} the per-submission frontier baseline (\BaseQualityRate\%; exact McNemar $p{=}0.008$), whose unconstrained generations bust the cap on 14\% of instances.
The one-off synthesis cost of \$\BuildUsdPerProblem{} per assignment is recouped after $\approx$\BreakEvenN{} repaired submissions---below the 337 buggy submissions per assignment this corpus averages in a \emph{single} offering---and thereafter each repair costs \AsymReduction--$2.5\times$ less.
The alternatives this observation invites do not close the gap: PyDex-style few-shot prompting (same-assignment example fixes plus execution feedback) raises cost $2.4\times$ without raising quality (85.5\%); the non-LLM Refactory tool, given \emph{every} correct student solution, passes tests on 90.5\% but busts the cap on a third of instances (56.0\% quality); a FrugalGPT-style cheap-model cascade floors at 88.5\% for $1.8\times$ \textsc{CoEP}'s marginal cost.
Composed with that cascade as its fallback, \textsc{CoEP} attains both the study's highest quality repair rate (90.5\%) and its lowest marginal cost ($2.5\times$ below the frontier baseline).

This paper makes the following contributions:
\begin{itemize}
\item \textbf{A new deployment paradigm for assignment repair.} We identify the many-instances, one-specification structure of programming-assignment APR and formulate \emph{per-assignment repairer synthesis}: amortizing LLM reasoning into a reusable, locally executable repair artifact, with a cost model and break-even analysis for when it pays off.
\item \textbf{The \textsc{CoEP} system.} A builder agent that synthesizes per-assignment repairers through a generate--validate--refine loop \citep{selfrefine2023,reflexion2023} over a repair-operator library; repairers are independently re-validated (test-suite pass + relative-patch-size cap) so a repairer can never self-report success, and are backed by hybrid LLM escalation.
\item \textbf{A same-model evaluation on real student programs.} On \NumProblems{} assignments and 1{,}685 real buggy submissions from the public Refactory dataset, we compare both paradigms driven by the \emph{same} frontier model against seven baselines spanning three families---per-submission LLM repair (plain, cached, PyDex-style few-shot with execution feedback), cost-reduction alternatives (cheap model, FrugalGPT-style cascade, generic-search-only), and the classical non-LLM Refactory tool---under one validation harness, exact token-level cost accounting, and statistical tests; plus ablations isolating synthesized rules, refinement rounds, and builder-model capability.
\item \textbf{Artifacts.} We release the harness, dataset-import pipeline, prompts, synthesized repairers, and all raw model outputs.\footnote{Anonymized repository submitted as supplementary material.}
\end{itemize}

Two consequences follow.
(1)~\emph{Caching is a discount, not a fix.} Prompt caching bills the shared prefix at $0.1\times$ after a $1.25\times$ write \citep{anthropiccaching}, cutting per-submission cost from \$$\BaseUsdPerInst\times10^{-3}$ to \$$\CachedUsdPerInst\times10^{-3}$ in our setting (-\CacheSavingFrac\%)---but the submission-dependent tokens, all output tokens, and one frontier-model inference per submission remain, and cost still scales with enrollment.
(2)~\emph{The redundancy is exactly the amortizable part.} What is constant per assignment---understanding the specification, the tests, and the space of likely mistakes---can be reified \emph{once} into an executable artifact. That is the move \textsc{CoEP} makes, and the rest of the paper quantifies what it buys.

\subsection{Problem Formulation}
An \emph{assignment} is a triple $A = (d, T, R)$: a natural-language description $d$, a visible test suite $T = \{(x_i, y_i)\}$ over a designated entry function (individual tests may call named auxiliary functions the assignment requires), and a small set $R$ of reference solutions.
A \emph{repair} of a buggy submission $b$ is a program $p$ such that (i)~$p$ passes all of $T$ and (ii)~$\mathrm{RPS}(b,p) \le \tau$, where RPS is the token-level relative patch size---the Levenshtein distance between the lexical token sequences of $b$ and $p$, normalized by $|b|$---following the patch-size metrics of Refactory and PyDex \citep{refactory2019,pydex2024}.
The cap $\tau$ (we use $\tau = 0.35$) operationalizes the pedagogical requirement that a repair be feedback on the \emph{student's} program: it rules out replacing the submission with a reference solution, which passes tests but teaches nothing \citep{itsp2017}.

Conventional LLM-based APR maps each $b$ to a query $\mathrm{LLM}(d, T, b)$.
\textsc{CoEP} instead synthesizes, once per assignment, a \emph{repairer} $\rho_A : b \mapsto p \,\cup\, \{\bot\}$---an ordinary Python module with no model access---and deploys the hybrid
\[
\mathrm{repair}(b) =
\begin{cases}
\rho_A(b) & \text{if } \rho_A(b) \ne \bot \;(\approx 0\text{ cost})\\
\mathrm{LLM}(d, T, b) & \text{otherwise.}
\end{cases}
\]

\subsection{Repairer Synthesis}
A builder agent receives $d$, $T$, $R$, and $k{=}5$ historical buggy submissions $B_{\mathrm{build}}$, together with the documentation of a small \emph{repair-operator library} that we provide as the substrate for all synthesized repairers.
The library contributes three reusable capabilities:

\textbf{(1) Generic edit search.} \texttt{candidates\_generic} enumerates candidate patches by applying small semantic edits at every applicable AST site---comparison/arithmetic/Boolean operator swaps, integer off-by-one shifts, Boolean-constant flips, index shifts, and argument swaps---singly or in pairs. This is the inversion of the classical mutation-operator space \citep{mutants2014} and plays the role that hand-curated fix templates play in template-based APR \citep{par2013,tbar2019}.

\textbf{(2) Test-driven validation.} \texttt{first\_passing} runs candidates against the full suite $T$ in a sandbox and returns the first candidate that passes \emph{all} tests while satisfying the RPS cap. Synthesized code is contractually forbidden from returning an unvalidated patch.

\textbf{(3) Failure diagnosis.} \texttt{failing\_tests} exposes the failing-test pattern of the input program, letting repairers dispatch: e.g., a \texttt{sort\_age} submission whose output is sorted ascending rather than descending selects order-reversal rules before anything else.

The builder's essential creative work is the \emph{problem-specific rule set}: AST rewrite rules that anticipate the misconceptions students exhibit for \emph{this} assignment---in the real corpus we study, occurrence-count thresholds off by one in \texttt{unique\_day} (\texttt{>=2} where \texttt{!=1} is needed), a tuple accumulator that silently discards non-maximal elements in \texttt{sort\_age}, a helper copied from the previous exercise that compares \texttt{i[1]} on plain integers in \texttt{top\_k}---derived by studying $d$, $T$, $R$, and $B_{\mathrm{build}}$.
These rules generate edits far outside the generic operator space (rebuilding an empty function from the student's own auxiliary, moving a decision out of a loop, repointing a comparison at the right variable), and our ablation shows they, not the generic search, carry the paradigm (RQ3).

\begin{algorithm}[t]
\caption{Per-assignment repairer synthesis}
\label{alg:builder}
\begin{algorithmic}[1]
\REQUIRE assignment $(d,T,R)$, sample bugs $B_{\mathrm{build}}$, rounds $R_{\max}$
\STATE $\rho \leftarrow \mathrm{LLM}_{\mathrm{build}}(d, T, R, B_{\mathrm{build}}, \mathrm{lib})$ \hfill$\triangleright$ single shot
\FOR{$r = 2 \dots R_{\max}$}
  \STATE $F \leftarrow \{(b,\mathrm{outcome}(\rho,b)) : b \in B_{\mathrm{build}}\}$ \hfill$\triangleright$ harness
  \IF{all outcomes are \textsc{repaired}} \RETURN $\rho$ \ENDIF
  \STATE $\rho \leftarrow \mathrm{LLM}_{\mathrm{refine}}(\rho, F)$ \hfill$\triangleright$ single shot
\ENDFOR
\RETURN $\rho$
\end{algorithmic}
\end{algorithm}

\textbf{Generate--validate--refine.}
Because a single-shot synthesized module can contain its own defects, the harness closes the loop (Algorithm~\ref{alg:builder}): it installs the module, applies it to $B_{\mathrm{build}}$, \emph{independently} re-validates every returned patch (sandboxed test execution plus RPS check---the repairer's own claims are never trusted), and, if any sample bug is unrepaired, sends the module back with per-bug outcomes and the failing submissions for revision, up to $R_{\max}{=}3$ total rounds.
This is a deliberately austere instantiation of self-refinement \citep{selfrefine2023,reflexion2023}: every LLM interaction is a single prompt--response pair, so the entire build cost is the token count of at most $2R_{\max}$ message payloads, measured exactly.

\textbf{Deployment.}
The frozen repairer runs in a subprocess with a wall-clock budget (60s; observed mean \CoepMeanSec s) and no network access.
Its patches are re-validated by the grading harness before being shown to a student, so a defective repairer degrades to $\bot$ (escalation), never to a wrong ``repair''; escalated submissions follow the conventional per-submission LLM path, and their cost is counted against \textsc{CoEP} in every comparison.
(Caching past LLM \emph{patches} would amortize too, but a patch is specific to one buggy program; a synthesized rule generalizes over a misconception class, fixing submissions whose surface form was never seen.)

\section{Experimental Setup}
\label{sec:setup}

We ask three research questions:
\textbf{RQ1 (Effectiveness \& quality).} How do \textsc{CoEP}'s synthesized repairers compare to per-submission frontier-LLM repair in repair rate and patch quality?
\textbf{RQ2 (Cost).} What are the token/dollar costs of both paradigms, when does repairer synthesis break even, and what is the asymptotic saving?
\textbf{RQ3 (Sources of power).} How much do the synthesized problem-specific rules and the refinement rounds contribute?

\subsection{Dataset}
We evaluate on the Refactory dataset \citep{refactory2019}: real submissions by 361 university students to five assignments of a CS1 Python course at the National University of Singapore---the standard real-student corpus of the assignment-repair literature, used by Refactory, Verifix, PyDex, and AAAI-25's counterexample-guided repair \citep{verifix2022,pydex2024,orvalho2025}.
The assignments (\texttt{search}, \texttt{unique\_day}/\allowbreak\texttt{unique\_month}/\allowbreak\texttt{contains\_unique\_day}, \texttt{remove\_extras}, \texttt{sort\_age}, \texttt{top\_k}) span search, multi-function date logic, deduplication, sorting, and selection; one requires three separate functions, which our harness supports through per-test entry points.
We import each assignment's handout, its instructor test suite (5--11 input/output tests per assignment), and 3 reference solutions sampled from the instructor-provided reference plus correct student submissions (seed 7).
Of the corpus's 1{,}783 buggy submissions, 1{,}685 compile and fail at least one parsed test after import; from these, per assignment, 5 sampled submissions form the builder's $B_{\mathrm{build}}$ and 40 disjoint sampled submissions are held out for evaluation ($n{=}\NumEval$; seed 7, fixed before any experiment)---a size that keeps eight experimental arms tractable while giving $\pm$5pp Wilson intervals.

This corpus has circulated publicly since 2019 and is plausibly in the training data of every current LLM; we use it \emph{deliberately}.
Memorization, if present, inflates every LLM-driven arm symmetrically---the per-submission baselines and \textsc{CoEP}'s builder are the \emph{same model}---so paradigm comparisons remain valid, while the non-LLM tool and our generic search are unaffected; what memorization cannot do is pass our validation harness on the builder's behalf, since every patch is re-executed against the instructor tests.
We analyze the residual asymmetries in Discussion.

\subsection{Baselines}
\textbf{Per-submission LLM repair} is the deployment paradigm of PyDex/MMAPR, ChatRepair, and FastFixer \citep{pydex2024,mmapr2022,chatrepair2024,fastfixer2024}: one query per submission containing the handout, the visible tests, the buggy program, and minimal-patch instructions.
We instantiate it with the \emph{same} frontier model that powers \textsc{CoEP}'s builder, so every observed difference is attributable to the paradigm, not the model.
\textbf{PyDex-style few-shot repair} enriches each query with the two ingredients PyDex found most effective \citep{pydex2024}: five real (buggy, fixed-by-the-same-student) example pairs from the \emph{same} assignment---drawn from $B_{\mathrm{build}}$ students where their own later fix passes the suite, never from evaluation submissions---plus the submission's concrete failing-test feedback.
This gives the per-submission paradigm the same assignment-specific information budget \textsc{CoEP}'s builder receives.
\textbf{Cached per-submission repair} re-prices the plain queries under provider prompt caching (shared prefix written once at $1.25\times$, read at $0.1\times$) \citep{anthropiccaching}.
\textbf{Cheap-model repair and cascade}: the same per-submission queries executed by a Haiku-tier model (\$1/\$5 per Mtok), alone and in a FrugalGPT-style cascade \citep{frugalgpt2024} that escalates its quality failures to the frontier model---the strongest \emph{zero-build-cost} competitors to amortization.
\textbf{Generic-hybrid}: our generic edit search run with no LLM synthesis at all, backed by the same frontier fallback---the strongest free local competitor, and an ablation of the synthesized rules.
\textbf{Refactory} \citep{refactory2019}, the classical non-LLM per-assignment tool, run in its strongest published configuration (online refactoring, structure mutation, block repair, 100\% sampling of correct solutions): for each assignment it receives \emph{all} correct student submissions (2{,}442 across the five assignments) plus the reference---orders of magnitude more per-assignment data than \textsc{CoEP}'s 3 references and 5 sample bugs---and its output programs are re-validated under our harness and metrics.

\subsection{Metrics}
\textbf{Test-pass rate}: fraction of evaluation submissions for which the system produces a program passing all visible tests \citep{refactory2019,pydex2024}.
\textbf{Quality repair rate} (primary): test-pass \emph{and} $\mathrm{RPS} \le 0.35$---the constraint \textsc{CoEP} enforces by construction, applied identically to every arm---since a test-passing rewrite that discards the student's approach is not usable feedback \citep{itsp2017}.
\textbf{Relative patch size (RPS)}: token-level edit distance normalized by program length \citep{refactory2019,pydex2024}; smaller is pedagogically better.
\textbf{Cost}: exact token counts of every prompt/response pair, priced at a representative frontier tier (\$3/\$15 per Mtok in/out; Claude Sonnet standard pricing, July 2026) with cache pricing as above, reported as tokens, USD per submission, and USD per assignment, following the per-bug cost accounting of ChatRepair \citep{chatrepair2024}.
Repair rates carry 95\% Wilson intervals; paired comparisons use exact McNemar tests.

\subsection{Protocol}
All LLM interactions---per-submission repairs in every LLM arm and every builder/refinement call---are single-shot prompt$\to$response exchanges executed by the stated model (Claude Sonnet or Haiku tier, July 2026 snapshots) under identical instructions, with no code execution or test access at generation time; all validation is performed by our harness.
Local search is deterministic; LLM calls are single-sample ($n{=}1$), matching the deployment setting of one repair attempt per submission.
Costs are computed from the exact message strings with a fixed tokenizer approximation applied identically to all arms (chars/3.6; provider tokenizers are unavailable offline); because the arms differ in input/output mix, we release every raw string for exact re-tokenization and note that a $\pm$20\% differential calibration error shifts break-even points by at most the same factor.
To probe sensitivity to builder capability, we additionally re-ran the entire synthesis pipeline with the Haiku-tier model as the builder (same prompts, same $R_{\max}$).
The Refactory tool ran in its original configuration ported to Python 3.11, on the same evaluation submissions.
Synthesized repairers used a 60s timeout and $\tau{=}0.35$ throughout; experiments ran on CPU only.

Table~\ref{tab:main} presents the headline comparison.
Every LLM arm passes the visible tests on essentially all submissions---confirming that on CS1-scale programs, functional repair is saturated \citep{pydex2024}---but \emph{quality} repair is not: 14\% of the frontier baseline's test-passing patches exceed the size cap, rewriting rather than repairing the student's program, the failure mode \citet{itsp2017} identified as pedagogically useless.
Enriching the prompt PyDex-style with real same-assignment example fixes and execution feedback does not help (85.5\%, $2.4\times$ the cost): the model's failure on these instances is not a knowledge gap that more context fills, but the absence of an enforced size discipline.
The classical Refactory tool, despite receiving every correct student solution, drops to 56.0\% under the same discipline---its refactor-and-synthesize patches average $0.386$ RPS across test-passing repairs, twice our cap---which quantifies on shared data the invasive-fix concern raised about symbolic tools \citep{orvalho2025}.

\textsc{CoEP}'s synthesized repairers alone fix \CoepRate\% at zero marginal LLM cost (mean 0.9\,s per submission on one CPU core), with the \emph{smallest} patches of any arm on the instances they repair (mean RPS 0.127 vs.\ the frontier's 0.187 over all its test-passing patches), and they are \emph{safe}: across \NumEval{} attempts, zero test-failing and zero over-cap patches were emitted---the only failure mode is abstention ($\bot$), never a wrong repair.
Escalating abstentions to the frontier model lifts the hybrid to \HybridRate\%, \emph{above} the per-submission baseline itself (\BaseQualityRate\%): on 8 submissions the size-capped local search finds a minimal repair where the baseline's one-shot generation overshoots the cap, and the reverse never occurs (exact McNemar, discordant $0{:}8$, $p{=}0.008$).
Guarantees, not just averages, change character: a prompt can \emph{request} minimality, but only a validator can \emph{enforce} it.

Per-assignment local rates (Figure~\ref{fig:perproblem}) range from 25\% (\texttt{remove\_extras}) to 85\% (\texttt{search}), tracking idiom diversity: \texttt{search}'s submissions are variations of one loop, while \texttt{remove\_extras} attracts a zoo of list-surgery styles whose bugs (aliasing, wrong-variable appends, mutation while iterating) defeat rules induced from five samples.
The hybrid absorbs this heterogeneity---and build-round trajectories signal it \emph{before} deployment, a natural routing cue for spending larger build budgets on harder assignments.

\subsection{RQ3: Where Does the Power Come From?}

\textbf{Synthesized rules vs.\ generic search.}
The generic-only ablation---the same operator library and validation, with no LLM-synthesized rules---repairs \AblRate\% of real student bugs (13/200), against \textsc{CoEP}'s \CoepRate\% (exact McNemar, discordant $0{:}82$, $p{<}10^{-24}$).
The collapse is diagnostic: real student bugs are almost never the single-operator slips that mutation-style edit search inverts.
They are misspelled variable names, thresholds off by an idiom (\texttt{>=2} for \texttt{!=1}), helpers copied from the previous exercise, decisions placed inside the wrong loop, accumulators of the wrong type---and the rules that fix them are structural rewrites no generic operator produces.
On this corpus, \emph{synthesized understanding is not an increment over search; it is 86\% of everything the local path repairs}.

\textbf{Refinement rounds.}
Two of five frontier builders passed all build samples in one shot; feedback rounds repaired the other three ($15/25 \to 25/25$ build success), and each diagnosis was a \emph{delivery} defect, not a comprehension one: the \texttt{unique\_day} builder's round-1 rules were semantically right but rendered patches through \texttt{ast.unparse}, whose whole-file reformatting blew the size cap on every candidate (round 2 switched to surgical line edits: $0/5 \to 5/5$); \texttt{sort\_age} twice produced correct-but-oversized rewrites before finding a 14-token insertion; \texttt{top\_k}'s rules never survived validation until round 3 emitted hand-verified corrected programs per structural pattern ($1/5 \to 5/5$).
Independent validation surfaces these defects and feedback with the still-failing submissions fixes them---single-shot synthesis would have shipped three broken repairers out of five.

\textbf{Builder capability.}
Re-running the entire synthesis pipeline with the Haiku-tier model as builder (same prompts, same $R_{\max}{=}3$) yields repairers that fix 10.0\% of held-out submissions (20/200), barely above the generic floor and far below the frontier builder's \CoepRate\%: only one of five cheap builders ever passed all build samples (final build success $14/25$ vs.\ $25/25$), two never repaired a single one, and their failure modes---whole-file reformatting, unvalidated candidates---are exactly the delivery defects the frontier builder learns to fix from feedback.
The cheap builder's rules cost \$0.022 per assignment but repair too little to matter; upgrading to the frontier builder's \$\BuildUsdPerProblem{} pays for itself within ${\approx}$230 submissions.
Repairer synthesis is thus a frontier-capability task---but building is a one-off cost, so that capability is bought once per assignment, not once per submission; that is the entire point.

\smallskip
\noindent\fbox{\parbox{0.965\columnwidth}{\textbf{RQ3.} On real bugs, generic edit search fixes 6.5\%---synthesized assignment-specific rules are 86\% of what the local path repairs ($p{<}10^{-24}$). Harness-driven refinement rescues three of five builders from delivery defects ($15/25 \to 25/25$ build success), and builder capability is decisive: a cheap-model builder achieves 10.0\% local repair vs.\ the frontier's \CoepRate\%.}}

\section{Discussion and Limitations}
\label{sec:limitations}

\textbf{Construct validity.}
Repair rate is measured against the instructor's visible tests, as in prior assignment-repair work \citep{refactory2019,pydex2024}; a patch could overfit the suite, and \textsc{CoEP}'s search optimizes that oracle directly.
The RPS cap bounds the degenerate form of that overfit (wholesale replacement), and it is the \emph{per-submission} arms that exceed it in practice---14\% of frontier patches, a third of the symbolic tool's---while the local path, which cannot emit an over-cap patch, produced zero unsafe outputs.
Our quality threshold ($\tau{=}0.35$) follows the patch-size discipline of Refactory and PyDex; sweeping it moves absolute rates but not orderings, since \textsc{CoEP}'s patches are the smallest per arm.
The cost model prices one provider tier; because we report raw token counts, any pricing can be substituted, and the break-even expression in RQ2 is closed-form in the price.

\textbf{Internal validity.}
Both paradigms use the same model, the same single-attempt budget, and the same independent validation harness; the builder sees 5 sample bugs and never the 40 evaluation submissions.
The corpus is public since 2019, so training-data contamination is possible---and, by design, \emph{symmetric}: the same model powers every LLM arm, so memorization inflates the baseline at least as much as the builder, whose output must additionally survive execution against the instructor tests, which memorized text cannot do on its own.
The observed failure modes corroborate this: a builder reciting known fixes would not need refinement rounds to repair \texttt{ast.unparse} formatting defects, and the cheap builder---with the same putative memorized knowledge---would not collapse to 10\%.
LLM calls ran through an agent harness constrained to a stateless single-shot endpoint (no tool use, no test execution); costs are computed from the exact message payloads under a fixed approximate tokenizer applied to all arms, so ratios and break-evens are unaffected by calibration error, and we release all raw strings for exact re-tokenization.

\textbf{External validity.}
We evaluate five assignments from one course, one language, and one model family (two tiers); multi-function projects beyond \texttt{unique\_day}'s three functions are open.
Our evaluation subsamples 40 buggy submissions per assignment (seeded, fixed before any experiment) from the 1{,}685 available; Wilson intervals quantify the resulting uncertainty, and the raw corpus supports scaling any arm.
The local repair rate is heterogeneous (25--85\% by assignment) and bounded by what five sample bugs can teach; richer build sets, misconception taxonomies, or clustering the assignment's full submission history \citep{clara2018} are natural extensions the framework prices explicitly.
The economics assume assignments recur at scale---the regime of this corpus itself (108--557 buggy submissions per assignment per offering) and of MOOCs.

\section{Related Work}
\label{sec:related}

\textbf{APR for programming assignments.}
Pre-LLM systems exploit per-assignment structure---CLARA's clustering \citep{clara2018}, Sarfgen's aligned-example search \citep{sarfgen2018}, Refactory's refactoring-based repair \citep{refactory2019}, Verifix's verified alignment \citep{verifix2022}---and \citet{itsp2017} established test-based repair rates and the feedback-suitability concern behind patch-size metrics; all are cheap per submission but need many prior correct solutions or hand-built machinery, and our head-to-head run shows the quality cost of the latter's invasive patches on shared data.
At AAAI, the setting remains active from the per-submission side: counterexample-guided repair \citep{orvalho2025} and minimal-modification adaptive repair \citep{adapr2025}.
\textsc{CoEP} keeps the classical per-assignment amortization but replaces the machinery with LLM synthesis from a handful of examples.

\textbf{LLM-based repair.}
AlphaRepair recast repair as generation \citep{alpharepair2022}; ChatRepair adds conversational test feedback and per-bug cost accounting \citep{chatrepair2024}; PyDex/MMAPR target student programs \citep{pydex2024,mmapr2022}; FastFixer accelerates per-query inference \citep{fastfixer2024}; CREF adds a tutor in the loop \citep{cref2024}.
All are per-submission; \textsc{CoEP} is complementary (any can serve as its fallback) but shifts the primary cost to the assignment.

\textbf{Template- and pattern-based APR.}
PAR and TBar showed that a fixed library of human-curated fix templates repairs a surprising share of real bugs \citep{par2013,tbar2019}.
\textsc{CoEP}'s generic operator layer is a mutation-inversion instance of this idea \citep{mutants2014}; its novelty is the \emph{synthesized, assignment-specific} template layer, authored per specification by an LLM rather than curated globally by humans.

\textbf{Cost-efficient LLM inference.}
FrugalGPT's cascades route queries between models of different prices \citep{frugalgpt2024}; SRepair engineers cheap open-model pipelines (\$0.029/bug) \citep{srepair2024}; provider prompt caching discounts repeated prefixes \citep{anthropiccaching,openaicaching}.
All optimize \emph{within} the pay-per-query paradigm and are composable with \textsc{CoEP} (our cached baseline; a cheaper fallback model).
\textsc{CoEP} instead removes queries: the majority of submissions never reach a model.

\textbf{LLMs synthesizing reusable tools.}
Voyager's skill library and LLMs-as-tool-makers show agents that write reusable code artifacts amortized across future episodes \citep{voyager2024,toolmakers2024}, and self-refinement loops improve one-shot generations \citep{selfrefine2023,reflexion2023}.
\textsc{CoEP} carries this idea into APR with two twists that the education setting forces: the synthesized tool must be \emph{verifiable} (test-suite validation, never-trust-self-reports) and \emph{quality-constrained} (RPS cap), because its output is feedback to a learner.

\section{Conclusion}
Programming-assignment repair has a structure that per-submission LLM querying ignores and per-assignment synthesis exploits: one specification, many failures, recurring misconceptions.
On real student programs, \textsc{CoEP} turns 26 cents of frontier-model reasoning into a permanent, local, verifiable repairer per assignment---and the resulting hybrid \emph{beats} the per-submission paradigm on quality repairs (90.5\% vs.\ 86.0\%) at $1.9$--$2.5\times$ lower marginal cost, breaking even inside a single course offering.
Per-assignment synthesis is one instance of a broader recipe---\emph{amortize LLM reasoning into verifiable executable artifacts wherever many instances share a specification}---that applies to grading rubrics, hint generation, and beyond.

\section*{Ethical Statement}
\textsc{CoEP} automates feedback, not grading, and should deploy under instructor oversight.
\emph{Fairness}: students whose approaches a repairer cannot handle receive full-LLM treatment---never degraded service---and local repair is deterministic and auditable.
\emph{Learning displacement}: the RPS cap keeps output as minimal, explainable edits; deployments can surface failing tests before patches.
Student programs come from the publicly released, de-identified Refactory dataset; no new human-subject data are introduced.
