\begin{abstract}
Large language models (LLMs) repair buggy submissions to programming assignments well, but they are deployed \emph{one query per submission}: every request re-transmits the same assignment description and test suite, so cost grows linearly with enrollment and recurs every term, while caching and cheaper models shrink only the constant, not the structure.
Observing that assignment repair is a \emph{many-instances, one-specification} regime, we propose \textsc{CoEP}, a framework that shifts LLM investment from the submission to the assignment.
An LLM agent reads the specification, tests, and a few sample programs once, and synthesizes an executable symbolic repairer---problem-specific AST rewrite rules over a generic bounded edit search---whose every patch is independently test-validated and size-capped.
Refined through validation feedback and then deployed locally, the repairer fixes subsequent submissions at zero marginal LLM cost, escalating the rest to conventional per-submission repair so that coverage is never sacrificed; it is also a transparent artifact that instructors can audit, produces minimal patches by construction, and repairs locally in under a second.
Experiments on real student programs, against per-submission LLM repair, a symbolic non-LLM tool, and cost-reduction alternatives such as caching and model cascades, show that amortizing LLM reasoning into a verifiable per-assignment artifact preserves repair quality while fundamentally improving the cost structure of serving many instances of one specification.
\end{abstract}

\section{Introduction}

Timely, individualized feedback is the scarcest resource in programming education: introductory courses enroll hundreds of students on campus and tens of thousands online, each producing buggy submissions no instructor can examine one by one.
Automated program repair (APR) has therefore long been proposed as a feedback engine for programming assignments: given a buggy submission and the assignment's test suite, produce a small patch that makes it correct while preserving the student's own approach \citep{itsp2017,clara2018,sarfgen2018,refactory2019,verifix2022}.

Large language models (LLMs) have made this vision practical.
LLM-based repair now fixes the large majority of real student programs---up to 96.5\% of buggy Python submissions in PyDex \citep{pydex2024}---at modest per-bug prices \citep{chatrepair2024,alpharepair2022,fastfixer2024,cref2024}.
But these systems all share a deployment paradigm that we argue is mismatched with the economics of the classroom: \emph{every buggy submission triggers a fresh LLM query} that re-transmits the assignment description, the test suite, and formatting instructions before the model ever sees the student's code.
On the real student corpus we study, 77\% of the input tokens of a per-submission repair prompt are byte-identical across all submissions to the same assignment (\PrefixFrac\% in a contiguous cacheable prefix); the student's code is 23\% of what the course pays to process, query after query, semester after semester.
Provider-side prompt caching \citep{anthropiccaching,openaicaching} discounts redundant prefixes but does not change the paradigm---here it cannot even engage, since the entire 439-token prompt sits below the provider's 1{,}024-token cacheable minimum---and every submission still requires a frontier-model round trip, with the attendant marginal cost, latency, rate limits, and external dependence.

Our key observation is that assignment repair is a \emph{many-instances, one-specification} regime: a single assignment is attempted by hundreds of students whose failures cluster into recurring misconceptions \citep{clara2018,refactory2019}.
Pre-LLM systems exploited exactly this structure (CLARA clustered correct solutions; Refactory refactored them into a per-problem search space), cheap per submission but needing hand-built machinery or large solution pools; per-submission LLM repair inverts the trade-off, automatic and general but paying for the same specification-level reasoning on every query.

We propose to get both halves: \textbf{spend the LLM once per assignment, not once per submission}.
In \textsc{CoEP} (\underline{Co}st-\underline{E}ffective \underline{P}rogram repair), an LLM agent receives the assignment specification, test suite, a few reference solutions, and a handful of historical buggy submissions, and \emph{writes a program repairer}: a deterministic Python module combining problem-specific rewrite rules with a generic edit-search library, validating every candidate against the visible tests under a patch-size cap.
After at most three harness-driven refinement rounds it is frozen and deployed: submissions are repaired \emph{locally}, in under a second on average, at zero marginal LLM cost, and any the repairer cannot fix escalate to the conventional LLM path---so the hybrid never does worse than the paradigm it replaces.

On \NumProblems{} real assignments from the public Refactory dataset \citep{refactory2019}---1{,}685 buggy Python submissions written by university CS1 students---holding the underlying LLM fixed across all conditions, \textsc{CoEP}'s synthesized repairers alone fix half of held-out submissions at zero marginal LLM cost (50.7\% [48.3, 53.1] on the full corpus), and the central result is one of \emph{inheritance}: fronting any per-submission protocol with \textsc{CoEP} preserves that protocol's quality set---verified instance by instance---while cutting its marginal cost $1.8$--$1.9\times$.
Against the deployed plain-prompt convention the hybrid additionally repairs strictly more within the patch-size cap (\HybridRate\% vs.\ \BaseQualityRate\%; 8 unique wins, none reversed, in 3 of 5 assignments---submission-level $p{=}0.008$, suggestive at cluster level), because unconstrained generations bust the cap on 14\% of instances.
The one-off synthesis cost of \$\BuildUsdPerProblem{} per assignment is recouped after $\approx$\BreakEvenN{} repaired submissions on corpus-average economics---below the 337 buggy submissions per assignment this corpus averages in a \emph{single} offering---with per-assignment break-evens of 38--704 disclosed in RQ2.
The alternatives this observation invites do not close the gap: PyDex-style few-shot prompting raises cost $2.4\times$ without raising quality (85.5\%); the non-LLM Refactory tool, given \emph{every} correct student solution, passes tests on 90.5\% but busts the cap on a third of instances (56.0\% quality); a cheap-model cascade floors at 88.5\% for $1.8\times$ \textsc{CoEP}'s marginal cost; and granting the baseline \textsc{CoEP}'s own enforcement---a size validator with one feedback retry---reaches 98.5\%, but at \$3.26$\times10^{-3}$ per submission.
\textsc{CoEP} composes with all of them: fronting the cascade delivers 90.5\% at the lowest marginal cost of any arm above 86\% quality, and fronting the enforced-retry protocol repairs the \emph{identical} 98.5\% at $1.8\times$ lower cost---for every fallback, the same quality at a smaller slope.

This paper makes the following contributions:
\begin{itemize}
\item \textbf{A new deployment paradigm for assignment repair.} We identify the many-instances, one-specification structure of programming-assignment APR and formulate \emph{per-assignment repairer synthesis}: amortizing LLM reasoning into a reusable, locally executable repair artifact, with a cost model and break-even analysis for when it pays off.
\item \textbf{The \textsc{CoEP} system.} A builder agent that synthesizes per-assignment repairers through a generate--validate--refine loop \citep{selfrefine2023,reflexion2023} over a repair-operator library; repairers are independently re-validated (test pass + patch-size cap) so they can never self-report success, and are backed by hybrid LLM escalation.
\item \textbf{A same-model evaluation on real student programs.} On \NumProblems{} assignments and 1{,}685 real buggy submissions from the public Refactory dataset, we compare both paradigms driven by the \emph{same} frontier model against eight baselines spanning per-submission LLM repair (plain, cached, few-shot, enforced-retry), cost-reduction alternatives (cheap model, cascade, generic-search-only), and the non-LLM Refactory tool---under one validation harness, uniform cost accounting, and statistical tests; plus ablations isolating synthesized rules, refinement rounds, and builder capability.
\item \textbf{Artifacts.} We release the harness, dataset-import pipeline, prompts, synthesized repairers, and all raw model outputs.\footnote{Anonymized repository submitted as supplementary material.}
\end{itemize}

\section{The Cost Anatomy of Per-Submission Repair}
\label{sec:anatomy}

To make the redundancy argument concrete, we decompose the per-submission repair prompt used by our baseline (and, mutatis mutandis, by PyDex- and ChatRepair-style systems \citep{pydex2024,chatrepair2024}).
Averaged over the Refactory corpus, a single repair query consumes \BaseInTok{} input and \BaseOutTok{} output tokens: a task preamble with the assignment description and visible tests (241 tokens, 55\%), the buggy-submission section (99 tokens, 23\%---the \emph{only} part that varies between submissions to the same assignment), and fixed task instructions (99 tokens, 23\%).
77\% of every query is thus byte-identical across a class, and only the contiguous \PrefixFrac\% prefix ahead of the code is even cacheable; richer prompt styles widen the gap (the PyDex-style few-shot variant re-transmits 1{,}493 identical tokens per query, 88\% of its input).

Two consequences follow.
(1)~\emph{Caching is a discount, not a fix---and here, not even a discount.} Prompt caching bills a shared prefix at $0.1\times$ after a $1.25\times$ write \citep{anthropiccaching}; with no minimum it would cut per-submission cost \CacheSavingFrac\%, but CS1 repair prompts (\BaseInTok{} tokens) fall below the provider's 1{,}024-token cacheable minimum, so even that bound is unreachable; caching does engage on the bloated few-shot prompt (1{,}705 tokens; \$6.5 to \$2.9$\times10^{-3}$)---the redundancy is real, but provider caching serves it at the wrong granularity.
(2)~\emph{The redundancy is exactly the amortizable part.} What is constant per assignment---understanding the specification, the tests, and the space of likely mistakes---can be reified \emph{once} into an executable artifact. That is the move \textsc{CoEP} makes, and the rest of the paper quantifies what it buys.

\subsection{Problem Formulation}
An \emph{assignment} is a triple $A = (d, T, R)$: a natural-language description $d$, a visible test suite $T = \{(x_i, y_i)\}$ over a designated entry function (individual tests may call named auxiliary functions the assignment requires), and a small set $R$ of reference solutions.
A \emph{repair} of a buggy submission $b$ is a program $p$ such that (i)~$p$ passes all of $T$ and (ii)~$\mathrm{RPS}(b,p) \le \tau$, where RPS is the token-level relative patch size---the Levenshtein distance between the lexical token sequences of $b$ and $p$, normalized by $|b|$---following the patch-size metrics of Refactory and PyDex \citep{refactory2019,pydex2024}.
The cap $\tau$ (we use $\tau = 0.35$) operationalizes the pedagogical requirement that a repair be feedback on the \emph{student's} program: it rules out replacing the submission with a reference solution, which passes tests but teaches nothing \citep{itsp2017}.

Conventional LLM-based APR maps each $b$ to a query $\mathrm{LLM}(d, T, b)$.
\textsc{CoEP} instead synthesizes, once per assignment, a \emph{repairer} $\rho_A : b \mapsto p \,\cup\, \{\bot\}$---an ordinary Python module with no model access---and deploys the hybrid $\mathrm{repair}(b) = \rho_A(b)$ if $\rho_A(b) \ne \bot$ (at ${\approx}0$ cost), else $\mathrm{LLM}(d, T, b)$.

\subsection{Repairer Synthesis}
A builder agent receives $d$, $T$, $R$, and $k{=}5$ historical buggy submissions $B_{\mathrm{build}}$, together with the documentation of a small \emph{repair-operator library} that we provide as the substrate for all synthesized repairers.
The library contributes three reusable capabilities:

\textbf{(1) Generic edit search.} \texttt{candidates\_generic} enumerates candidate patches by applying small semantic edits at every applicable AST site---comparison/arithmetic/Boolean operator swaps, integer off-by-one shifts, Boolean-constant flips, index shifts, and argument swaps---singly or in pairs. This is the inversion of the classical mutation-operator space \citep{mutants2014} and plays the role that hand-curated fix templates play in template-based APR \citep{par2013,tbar2019}.

\textbf{(2) Test-driven validation.} \texttt{first\_passing} runs candidates against the full suite $T$ in a sandbox and returns the first that passes \emph{all} tests within the RPS cap; synthesized code is contractually forbidden from returning an unvalidated patch.

\textbf{(3) Failure diagnosis.} \texttt{failing\_tests} exposes the input program's failing-test pattern, letting repairers dispatch (e.g., output sorted ascending rather than descending selects order-reversal rules first).

The builder's essential creative work is the \emph{problem-specific rule set}: AST rewrite rules that anticipate the misconceptions students exhibit for \emph{this} assignment---occurrence thresholds off by an idiom in \texttt{unique\_day} (\texttt{>=2} for \texttt{!=1}), a tuple accumulator discarding non-maxima in \texttt{sort\_age}, a helper copied from the previous exercise in \texttt{top\_k}---derived from $d$, $T$, $R$, and $B_{\mathrm{build}}$.
These rules generate edits far outside the generic operator space, and our ablation shows they, not the generic search, carry the paradigm (RQ3).

\textbf{Generate--validate--refine.}
Because a single-shot synthesized module can contain its own defects, the harness closes the loop: it installs the module, applies it to $B_{\mathrm{build}}$, \emph{independently} re-validates every returned patch (sandboxed test execution plus RPS check---the repairer's own claims are never trusted), and, if any sample bug is unrepaired, sends the module back with per-bug outcomes and the failing submissions for revision, up to $R_{\max}{=}3$ total rounds.
This is a deliberately austere instantiation of self-refinement \citep{selfrefine2023,reflexion2023}: every LLM interaction is a single prompt--response pair, so the entire build cost is the token count of at most $2R_{\max}$ message payloads, measured directly from the raw strings.

\textbf{Deployment.}
The frozen repairer runs in a subprocess with a wall-clock budget (60s; observed mean \CoepMeanSec s) and no network access; its patches are re-validated by the grading harness before reaching a student, so a defective repairer degrades to $\bot$ (escalation), never to a wrong ``repair'', and escalations follow the conventional per-submission path with their cost counted against \textsc{CoEP} in every comparison.
(Caching past \emph{patches} would amortize too, but a patch is specific to one buggy program; a synthesized rule generalizes over a misconception class.)

\section{Experimental Setup}
\label{sec:setup}

We ask three research questions:
\textbf{RQ1 (Effectiveness \& quality).} How do \textsc{CoEP}'s synthesized repairers compare to per-submission frontier-LLM repair in repair rate and patch quality?
\textbf{RQ2 (Cost).} What are the token/dollar costs of both paradigms, when does repairer synthesis break even, and what is the asymptotic saving?
\textbf{RQ3 (Sources of power).} How much do the synthesized problem-specific rules and the refinement rounds contribute?

\subsection{Dataset}
We evaluate on the Refactory dataset \citep{refactory2019}: real submissions by 361 university students to five assignments of a CS1 Python course at the National University of Singapore---the standard real-student corpus of the assignment-repair literature, used by Refactory, Verifix, PyDex, and AAAI-25's counterexample-guided repair \citep{verifix2022,pydex2024,orvalho2025}.
The assignments (\texttt{search}, \texttt{unique\_day}/\allowbreak\texttt{unique\_month}/\allowbreak\texttt{contains\_unique\_day}, \texttt{remove\_extras}, \texttt{sort\_age}, \texttt{top\_k}) span search, multi-function date logic, deduplication, sorting, and selection; one requires three separate functions, which our harness supports through per-test entry points.
We import each assignment's handout, its instructor test suite (5--11 input/output tests per assignment), and 3 reference solutions sampled from the instructor-provided reference plus correct student submissions (seed 7).
Of the corpus's 1{,}783 buggy submissions, 1{,}685 compile and fail at least one parsed test after import; from these, per assignment, 5 sampled submissions form the builder's $B_{\mathrm{build}}$ and 40 disjoint sampled submissions are held out for evaluation ($n{=}\NumEval$; seed 7, fixed before any experiment)---a size that keeps eight experimental arms tractable at $\pm$5--7pp Wilson intervals.

This corpus has circulated publicly since 2019 and is plausibly in the training data of every current LLM; we use it \emph{deliberately}.
Memorization, if present, inflates every LLM-driven arm symmetrically---the per-submission baselines and \textsc{CoEP}'s builder are the \emph{same model}---so paradigm comparisons remain valid, while the non-LLM tool and our generic search are unaffected; what memorization cannot do is pass our validation harness on the builder's behalf, since every patch is re-executed against the instructor tests.
We analyze the residual asymmetries in Discussion.

\subsection{Baselines}
\textbf{Per-submission LLM repair} is the deployment paradigm of PyDex/MMAPR, ChatRepair, and FastFixer \citep{pydex2024,mmapr2022,chatrepair2024,fastfixer2024}: one query per submission containing the handout, the visible tests, the buggy program, and minimal-patch instructions.
We instantiate it with the \emph{same} frontier model that powers \textsc{CoEP}'s builder, so every observed difference is attributable to the paradigm, not the model.
\textbf{PyDex-style few-shot repair} enriches each query with the two ingredients PyDex found most effective \citep{pydex2024}: five real (buggy, fixed-by-the-same-student) example pairs from the \emph{same} assignment---drawn from $B_{\mathrm{build}}$ students where their own later fix passes the suite, never from evaluation submissions---plus the submission's concrete failing-test feedback.
This gives the per-submission paradigm the same assignment-specific information budget \textsc{CoEP}'s builder receives.
\textbf{Cached per-submission repair} re-prices the plain queries under provider prompt caching (shared prefix written once at $1.25\times$, read at $0.1\times$) \citep{anthropiccaching}.
\textbf{Cheap-model repair and cascade}: the same per-submission queries executed by a Haiku-tier model (\$1/\$5 per Mtok), alone and in a FrugalGPT-style cascade \citep{frugalgpt2024} that escalates its quality failures to the frontier model---the strongest \emph{zero-build-cost} competitors to amortization.
\textbf{Generic-hybrid}: our generic edit search run with no LLM synthesis at all, backed by the same frontier fallback---the strongest free local competitor, and an ablation of the synthesized rules.
\textbf{Refactory} \citep{refactory2019}, the classical non-LLM per-assignment tool, run in its strongest published configuration (online refactoring, structure mutation, block repair, 100\% sampling of correct solutions): for each assignment it receives \emph{all} correct student submissions (2{,}442 across the five assignments) plus the reference---orders of magnitude more per-assignment data than \textsc{CoEP}'s 3 references and 5 sample bugs---and its output programs are re-validated under our harness and metrics.

\subsection{Metrics}
\textbf{Test-pass rate}: fraction of evaluation submissions for which the system produces a program passing all visible tests \citep{refactory2019,pydex2024}.
\textbf{Quality repair rate} (primary): test-pass \emph{and} $\mathrm{RPS} \le 0.35$---the constraint \textsc{CoEP} enforces by construction, applied identically to every arm---since a test-passing rewrite that discards the student's approach is not usable feedback \citep{itsp2017}.
\textbf{Relative patch size (RPS)}: token-level edit distance normalized by program length \citep{refactory2019,pydex2024}; smaller is pedagogically better.
\textbf{Cost}: token counts of every raw prompt/response string under one fixed convention, priced at a representative frontier tier (\$3/\$15 per Mtok in/out; Claude Sonnet standard pricing, July 2026) with cache pricing as above, reported as tokens, USD per submission, and USD per assignment, following the per-bug cost accounting of ChatRepair \citep{chatrepair2024}.
Repair rates carry 95\% Wilson intervals; paired comparisons use exact McNemar tests at the submission level, and because submissions cluster within five assignments, we report per-assignment directions alongside every pooled test.

\subsection{Protocol}
All LLM interactions---per-submission repairs in every LLM arm and every builder/refinement call---are single-shot prompt$\to$response exchanges executed by the stated model (Claude Sonnet or Haiku tier, July 2026 snapshots) under identical instructions, with no code execution or test access at generation time; all validation is performed by our harness.
Local search is deterministic; LLM calls are single-sample ($n{=}1$), matching the deployment setting of one repair attempt per submission.
Costs are computed from the exact message strings with a fixed tokenizer approximation applied identically to all arms (chars/3.6; provider tokenizers are unavailable offline); because the arms differ in input/output mix, we release every raw string for exact re-tokenization and note that a $\pm$20\% differential calibration error shifts break-even points by at most the same factor.
To probe sensitivity to builder capability, we additionally re-ran the entire synthesis pipeline with the Haiku-tier model as the builder (same prompts, same $R_{\max}$).
The Refactory tool ran in its original configuration ported to Python 3.11, on the same evaluation submissions.
Synthesized repairers used a 60s timeout and $\tau{=}0.35$ throughout; experiments ran on CPU only.

Every LLM arm passes the visible tests on essentially all submissions---on CS1-scale programs, functional repair is saturated \citep{pydex2024}---but \emph{quality} repair is not: 14\% of the frontier baseline's test-passing patches exceed the size cap, rewriting rather than repairing the student's program \citep{itsp2017}.
PyDex-style enrichment with real same-assignment example fixes and execution feedback does not help (85.5\%, $2.4\times$ the cost): the failure is not a knowledge gap that more context fills, but the absence of an enforced size discipline.
The classical Refactory tool, despite receiving every correct student solution, drops to 56.0\% under the same discipline (its patches average $0.386$ RPS across test-passing repairs, twice our cap), quantifying on shared data the invasive-fix concern about symbolic tools \citep{orvalho2025}.

\textsc{CoEP}'s synthesized repairers alone fix \CoepRate\% at zero marginal LLM cost (mean \CoepMeanSec\,s per submission on one CPU core), with patches comfortably inside the cap (mean RPS 0.127; on the 87 instances both repair, the frontier's accepted patches are slightly smaller, 0.093 vs.\ 0.115), and they are \emph{safe}: across \NumEval{} attempts, zero test-failing and zero over-cap patches were emitted---the only failure mode is abstention ($\bot$), never a wrong repair.
The local path's advantage is therefore not average patch size but \emph{enforcement}: escalating abstentions to the frontier model lifts the hybrid to \HybridRate\%, above the per-submission baseline itself (\BaseQualityRate\%), because on 8 submissions the size-capped local search finds a minimal repair where the baseline's one-shot generation overshoots the cap (exact McNemar, discordant $0{:}8$, $p{=}0.008$; the ordering is never reversed in any assignment; strictly better in three, tied in two).
The tool comparison is no artifact of re-validation: Refactory's own oracle reports 91.0\% on these runs, within a point of our 90.5\% test-pass figure---the gap under our \emph{quality} metric is entirely its patch sizes.
Guarantees, not just averages, change character: a prompt can \emph{request} minimality, but only a validator can \emph{enforce} it---a point we return to with an enforcement-parity baseline in RQ2.

Scaling the zero-marginal local arm to the \emph{full} corpus (all 1{,}660 non-build submissions) confirms the estimate tightly: 50.7\% coverage [48.3, 53.1], per-assignment 27.9--71.4\%, the dispersion tracking idiom diversity; the hybrid absorbs it, and build-round trajectories signal it \emph{before} deployment---a routing cue for larger build budgets on harder assignments.

Table~\ref{tab:ladder} prices every configuration.
Within the pay-per-query paradigm the trade-off is stark: the cheap model saves $3\times$ but surrenders 21 quality points; caching is inapplicable to the plain prompt (the table's row is the no-minimum bound) and brings the few-shot variant only to \$2.91$\times10^{-3}$; and enforcement---a validator plus one minimality-feedback retry, the PyDex-style iterative protocol---lifts the frontier baseline to \RetryRate\% for \$\RetryUsd$\times10^{-3}$, the cheap model to 81.5\% for \$1.32, and the cascade (cheap self-retry before escalation) to 89.5\% for \$1.90: every zero-build configuration, enforced or not, stays below \textsc{CoEP}+cascade on quality, cost, or both.
The classical tool can also front the fallback: Refactory-then-frontier reaches 86.5\% at \$1.33$\times10^{-3}$ with zero build cost---but \textsc{CoEP}+cascade dominates it on \emph{both} axes, \textsc{CoEP}+frontier repairs strictly more ($7{:}0$, $p{=}0.016$), and the tool needs all 2{,}442 correct solutions and 5.5\,s/submission vs.\ 3 references, 5 bugs, and 0.9\,s.
The retry protocol defines this study's quality ceiling---and \textsc{CoEP} \emph{inherits} it: since the local path never emits an unsafe patch, fronting any protocol preserves its quality set while diverting half its traffic.
Empirically the inheritance is exact: \textsc{CoEP}+retry repairs the \emph{identical} 197/200 submissions as the retry arm (discordant $0{:}0$, per-assignment identical) at $1.8\times$ lower marginal cost, while \textsc{CoEP}+frontier beats the plain baseline outright ($p{=}0.008$) and \textsc{CoEP}+cascade does so at the lowest marginal cost of any quality-competitive arm ($p{=}0.004$; vs.\ the cascade alone, discordant $4{:}0$, n.s.; only the 65\%-quality Haiku arm is cheaper).
Hybrid cost stays linear in enrollment---the claim is a $1.8$--$2.5\times$ smaller slope plus an intercept, not zero marginal cost---and the slope shrinks as coverage grows.

Synthesizing an assignment's repairer costs \$\BuildUsdPerProblem{} on average (\BuildInTok{} prompt + \BuildOutTok{} response tokens across five assignments and ten builder calls; the price of ${\approx}$94 baseline repairs, paid once).
Let $C$ be the build cost and $\Delta$ the marginal saving per submission over a competitor; synthesis wins once $N > N^{*} = C/\Delta$.
Against the frontier baseline $N^{*}\!\approx\!\BreakEvenN$ (${\approx}154$ with cascade fallback); against the cascade itself ${\approx}295$; at matched 98.5\% quality, \textsc{CoEP}+retry recoups its build within ${\approx}173$.
Because build cost and coverage vary by assignment, so does $N^{*}$: computed per assignment with full-corpus coverage, \texttt{search}/\texttt{unique\_day}/\texttt{remove\_extras} break even at 38/88/241 submissions---inside their own single-offering volumes (557/417/306)---while \texttt{sort\_age} needs $\approx$1.2 offerings (368 vs.\ 297) and \texttt{top\_k} ($N^{*}{\approx}704$ vs.\ 108) pays off only at multi-offering or MOOC scale: amortization is per-assignment economics, and the build decision can be made per assignment from the build trajectory alone.
Composite-arm dollars are measured per-instance sums, not products of averages; escalated subsets cost more than average because escalation adversely selects harder, longer submissions (the frontier repairs 67\% of Haiku-escalated instances against 86\% overall), which is why, e.g., the cascade's \$1.94 exceeds the naive $0.90 + 0.35{\times}2.73 = \$1.86$.

Beyond cost, half of submissions are repaired in under a second on a CPU with no network dependency, rate limits, or nondeterminism---properties hosted per-query APIs do not offer, and that matter most at deadline-night spikes.

\subsection{RQ3: Where Does the Power Come From?}

\textbf{Synthesized rules vs.\ generic search.}
The generic-only ablation---the same operator library and validation, with no LLM-synthesized rules---repairs \AblRate\% of real student bugs (13/200), against \textsc{CoEP}'s \CoepRate\% (exact McNemar, discordant $0{:}82$, $p{<}10^{-24}$).
The collapse is diagnostic: real student bugs are almost never single-operator slips but misspelled names, thresholds off by an idiom (\texttt{>=2} for \texttt{!=1}), helpers copied from the previous exercise, wrong-type accumulators---structural rewrites no generic operator produces.
On this corpus, \emph{synthesized understanding is not an increment over search; it is 86\% of everything the local path repairs}.

\textbf{Refinement rounds.}
Two of five frontier builders passed all build samples in one shot; feedback rounds repaired the other three ($15/25 \to 25/25$), each from a \emph{delivery} defect, not a comprehension one---e.g., \texttt{unique\_day}'s round-1 rules were semantically right but rendered patches via \texttt{ast.unparse}, whose reformatting blew the cap on every candidate ($0/5 \to 5/5$ after switching to surgical line edits).
Validation surfaces these defects; feedback fixes them---single-shot synthesis would have shipped three broken repairers of five.

\textbf{Builder capability.}
Re-running the entire synthesis pipeline with the Haiku-tier model as builder (same prompts, same $R_{\max}{=}3$) yields repairers that fix 10.0\% of held-out submissions (20/200), barely above the generic floor: only one of five cheap builders ever passed all build samples ($14/25$ final build success vs.\ $25/25$), two never repaired a single one, and their failure modes---whole-file reformatting, unvalidated candidates---are exactly the delivery defects the frontier builder learns to fix from feedback.
Its rules cost \$0.022 per assignment but repair too little to matter; upgrading to the frontier builder pays for itself within ${\approx}$230 submissions---synthesis is a frontier-capability task, but that capability is bought once per assignment, not once per submission; that is the entire point.

\section{Discussion and Limitations}
\label{sec:limitations}

\textbf{Construct validity.}
Repair rate is measured against the instructor's visible tests, as in prior assignment-repair work \citep{refactory2019,pydex2024}; a patch could overfit the suite, and \textsc{CoEP}'s search optimizes that oracle directly, but the RPS cap bounds the degenerate form of that overfit (wholesale replacement)---and it is the \emph{per-submission} arms that exceed it in practice (14\% of frontier patches, a third of the tool's) while the local path produced zero unsafe outputs.
The threshold ($\tau{=}0.35$) follows Refactory and PyDex, and a $\tau$-sweep from stored patch sizes (Figure~\ref{fig:tau}) shows the orderings are not its artifact: the validated-retry arm dominates at every $\tau$, the hybrid tracks or exceeds the plain baseline for $\tau \ge 0.25$ (below that the recomputation is conservative---frozen repairers searched under $0.35$), and the tool's collapse appears at every threshold.
Because \textsc{CoEP}'s search optimizes the visible suite directly, suite overfitting favors it differentially; a hidden-oracle audit (60 seeded random inputs per assignment, differential against the reference) bounds the effect: 92.6\% of accepted local patches agree with the reference on every probe vs.\ 97.1\% of the baseline's---a measured 4.5pp differential, and a probe deployments can add as a third validator at zero LLM cost.
The cost model prices one tier from modeled (not billed) token counts; released raw strings let any pricing and tokenizer substitute into RQ2's closed-form break-even.

\textbf{Internal validity.}
Both paradigms use the same model and the same independent validation harness; the builder sees 5 sample bugs and never the 40 evaluation submissions.
Hybrid-vs-baseline McNemar tests are structurally one-sided (the hybrid contains the fallback) and submissions cluster in five assignments, where a sign test on the 8 unique wins (3 wins, 0 losses, 2 ties) is not significant---the quality edge over the plain baseline is consistent but suggestive; the load-bearing comparisons are the symmetric ones: the enforcement-parity arm (quality sets identical at lower cost) and patch sizes on shared instances.
Reusing cached \emph{patches} across near-duplicates would cover at most 33\% of evaluation instances (identical normalized-AST twin outside the split), below the rules' 50.7\%---rules generalize where retrieval cannot.
The corpus is public since 2019, so training-data contamination is possible---and, by design, \emph{symmetric}: the same model powers every LLM arm, so memorization inflates the baseline at least as much as the builder, whose output must additionally survive execution against the instructor tests; corroboratingly, a builder reciting known fixes would not need refinement rounds to repair \texttt{ast.unparse} formatting defects, nor would the cheap builder---with the same putative memorized knowledge---collapse to 10\%.
Each assignment reflects one stochastic builder trajectory; the refinement loop absorbed all three observed failures, and multi-seed replication is mechanical with the released harness.
LLM calls ran through an agent harness constrained to a stateless single-shot endpoint (no tool use, no test execution); costs are computed from the raw message payloads under one fixed approximate tokenizer, so uniform calibration error cancels in every ratio (a differential error shifts break-evens by at most its magnitude; Protocol), and we release all raw strings for exact re-tokenization.

\textbf{External validity.}
We evaluate five assignments from one course, one language, and one model family (two tiers); multi-function projects beyond \texttt{unique\_day}'s three are open.
LLM arms subsample 40 buggy submissions per assignment (seeded, fixed in advance) from the 1{,}685 available; the local arm's full-corpus re-run (RQ1) confirms the estimate.
Local repair is heterogeneous (28--71\% by assignment) and bounded by what five sample bugs can teach; richer build sets or clustering the full history \citep{clara2018} are extensions the framework prices explicitly, and the economics assume assignments recur at scale---this corpus's own regime (108--557 buggy submissions per assignment per offering).

\section{Related Work}
\label{sec:related}

\textbf{APR for programming assignments.}
Pre-LLM systems exploit per-assignment structure---CLARA's clustering \citep{clara2018}, Sarfgen's aligned examples \citep{sarfgen2018}, Refactory's refactoring \citep{refactory2019}, Verifix \citep{verifix2022}---and \citet{itsp2017} established test-based repair rates and the feedback concern behind patch-size metrics; all need many prior solutions or hand-built machinery, and our head-to-head run shows the quality cost of invasive patches.
At AAAI the setting stays active from the per-submission side: counterexample-guided and preference-tuned minimal repair at AAAI-25 \citep{orvalho2025,adapr2025}, and AAAI-26's learner-tailored repair, which retrieves per-assignment example fixes to guide each query \citep{lsgen2026}---amortizing \emph{data} into a retrieval index while every repair still pays for an LLM call (our PyDex-style arm bounds this design's economics).
\textsc{CoEP} instead amortizes \emph{reasoning} into an executable artifact and pays only on escalation.

\textbf{LLM-based repair.}
AlphaRepair recast repair as generation \citep{alpharepair2022}; ChatRepair adds conversational test feedback and per-bug cost accounting \citep{chatrepair2024}; PyDex/MMAPR target student programs \citep{pydex2024,mmapr2022}; FastFixer accelerates per-query inference \citep{fastfixer2024}; CREF adds a tutor in the loop \citep{cref2024}.
All are per-submission; \textsc{CoEP} is complementary (any can serve as its fallback) but shifts the primary cost to the assignment.

\textbf{Templates, cost-efficient inference, and tool synthesis.}
PAR and TBar showed a fixed library of human-curated fix templates repairs a surprising share of real bugs \citep{par2013,tbar2019}; \textsc{CoEP}'s generic layer is a mutation-inversion instance \citep{mutants2014}, and its novelty is the \emph{synthesized, assignment-specific} template layer, authored per specification by an LLM.
FrugalGPT cascades, SRepair's cheap pipelines, and provider caching \citep{frugalgpt2024,srepair2024,anthropiccaching,openaicaching} all optimize \emph{within} the pay-per-query paradigm and compose with \textsc{CoEP}, which instead removes queries.
Voyager and LLMs-as-tool-makers amortize agent-written code across episodes \citep{voyager2024,toolmakers2024}, with self-refinement improving one-shot generations \citep{selfrefine2023,reflexion2023}; \textsc{CoEP} adds the twists education forces---verifiable (never-trust-self-reports) and quality-constrained (RPS cap), because its output is feedback to a learner.

\section{Conclusion}
Programming-assignment repair has a structure per-submission querying ignores: one specification, many failures, recurring misconceptions.
On real student programs, \textsc{CoEP} turns 26 cents of frontier-model reasoning into a permanent, local, verifiable repairer per assignment; the hybrid beats the deployed per-submission paradigm on quality repairs (90.5\% vs.\ 86.0\%) and matches the strongest enforced-retry protocol exactly (98.5\%) at a $1.8$--$2.5\times$ smaller cost slope, breaking even inside one offering.
The recipe---\emph{amortize LLM reasoning into verifiable executable artifacts wherever many instances share a specification}---extends to rubrics, hints, and beyond.

\section*{Ethical Statement}
\textsc{CoEP} automates feedback, not grading, under instructor oversight; unhandled students get full-LLM treatment, local repair is auditable, and data are public.
