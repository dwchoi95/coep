\title{Use LLMs to Build Repair Tools, Not Patch Generation: Cost-Effective Automated Program Repair}
\author{Anonymous submission}
\affiliations{}

\begin{document}
\maketitle

\begin{abstract}
Large language models (LLMs) repair buggy submissions to programming assignments well, but they are deployed \emph{one query per submission}: every buggy program triggers a fresh model call, so cost, latency, and external dependence scale with enrollment and recur every term, while the specification-level reasoning being purchased is identical across a class. Caching and cheaper models shrink only the constant, not the structure. We propose \textsc{CoEP}, which moves the LLM from the marginal-cost to the fixed-cost column: \emph{spend the model once per assignment, not once per submission}. An LLM agent reads the assignment and a clustered sample of worked (buggy $\to$ fixed) pairs and authors the assignment-specific layer of a local repair tool: AST rewrite rules named after the misconceptions they fix, atop a shared symbolic substrate of generic edits and reference-guided minimal-hunk transplant from the class's own correct solutions. Every candidate patch is validated against the instructor's tests before it is kept; the tool can never self-report success, and submissions it abstains on escalate to a conventional per-submission call, so coverage is never sacrificed. On the standard benchmark of this literature, the synthesized tool repairs \emph{more} submissions with \emph{smaller} patches than the strongest hand-built symbolic tool, on that tool's own corpus and metric, with the entire model spend collapsed into a one-off synthesis plus a small escalation tail, so everything repaired locally costs no model call at all, offline and deterministically. A price-invariant break-even analysis shows when amortization wins and why cheaper models and caching do not change the answer, and the artifact yields what a per-query API cannot: reproducible minimal patches and a per-class misconception profile.
\end{abstract}

\section{Introduction}

Timely, individualized feedback is the scarcest resource in programming education: introductory courses enroll hundreds of students on campus and tens of thousands online, each producing buggy submissions no instructor can examine one by one. Automated program repair (APR) has therefore long been proposed as a feedback engine: given a buggy submission and the assignment's tests, produce a small patch that makes it correct while preserving the student's own approach \citep{itsp2017,clara2018,sarfgen2018,refactory2019,verifix2022}. Early systems established that the patch must stay close to the student's program, because an unrelated rewrite passes the tests but teaches nothing \citep{itsp2017}; a second generation mined the class's own accepted solutions, which repairs cheaply but fails whenever a submission matches no reference \citep{clara2018,sarfgen2018,refactory2019,verifix2022,orvalho2025}; LLM-based repair removed that constraint and now fixes most real student programs at modest per-bug prices \citep{pydex2024,mmapr2022,chatrepair2024,fastfixer2024}.

What the third generation fixed in coverage, it broke in cost structure. The deployment default is one model query per buggy submission, so spending grows with enrollment and restarts every term --- and the queries are massively redundant. A single assignment is attempted by hundreds of students whose failures cluster into a few recurring misconceptions \citep{clara2018,refactory2019}, and about two thirds of a query's input tokens are byte-identical across submissions to the same assignment. Paying a model to rediscover the same off-by-one for the three-hundredth time is not intelligence at work; it is a billing artifact. The standard remedies do not change the shape: cheaper tiers and provider caching shrink the constant \citep{anthropiccaching,openaicaching} --- and caching serves this redundancy at the wrong granularity, paying only for a shared leading prefix while the variable program comes first --- and retrieval enriches each query \citep{lsgen2026}, but every submission still triggers a round trip with its marginal cost, latency, and data egress. The question is not what a call costs, but where in the pipeline the LLM is invoked.

Our answer is to spend the LLM once per assignment. Agent research has shown LLMs can author reusable code and amortize it across uses \citep{toolmakers2024,voyager2024}, and classical synthesis has learned per-assignment fix rules from examples \citep{refazer2017}. \textsc{CoEP} (\underline{Co}st-\underline{E}ffective \underline{P}rogram repair) instantiates this for assignment repair: an LLM agent reads the assignment once and authors its problem-specific layer, AST rewrite rules named after the misconceptions they fix, running on a shared substrate of generic edits and reference-guided transplant from the class's correct pool. Every candidate patch must pass the instructor's tests before it is kept, so a tool can never self-report success. The frozen tool repairs locally in about a second at zero marginal LLM cost, and the few submissions it abstains on escalate to a conventional per-submission call.

The resulting artifact beats the hand-built state of the art on its own benchmark and metric --- \LocalRR\% repair rate at \LocalRPS{} mean relative patch size against Refactory's \RefacRR\% at \RefacRPS{} over \NumEvalRefac{} real student programs --- and against per-submission LLM repair on the full \NumEval-submission benchmark, coverage is at parity while the patch is a third smaller, for \$\HybridUsd{} against \$\PydexUsd. We are explicit about attribution: the rule layer produces \RuleShare\% of local fixes at a fifth the transplant's patch size and with a misconception label each, and the transplant produces the rest and is what carries coverage. The claim is not that an LLM wrote a state-of-the-art repairer. It is the invocation structure --- one cheap build plus a small escalation tail replaces an inference per submission, breaking even at eleven submissions per assignment --- and the artifact it feeds exceeds the hand-built tool.

The stakes scale with deployment. In one course the per-submission bill is dollars; on an online judge it is not. The public Codeforces dump our benchmark draws from aggregates 12.6M submissions to over 10{,}000 problems \citep{penedo2025codeforces}, and at the standard \$3/\$15 per Mtok rate our measured per-submission repair costs about \$125 per thousand, re-paid as every new submission arrives. The artifact also offers what per-submission inference cannot at any price: every patch is re-executed against the instructor's tests before it is emitted, it is deterministic and runs offline so student code never leaves the institution, and its rule-fired repairs aggregate into a per-class misconception profile that no API call returns.

\noindent This paper contributes:
\begin{itemize}\itemsep2pt \parskip0pt
\item \textbf{A cost-structure reformulation.} The LLM moves from per-submission marginal cost to per-assignment fixed cost, with a break-even $N^{*} = C_{\text{build}}/(\Delta(1{-}f))$ that is invariant to token price, so amortization is a structural advantage rather than one cheaper models erase.
\item \textbf{The \textsc{CoEP} system.} A builder agent synthesizes misconception-named AST rewrite rules through a generate--validate--refine loop \citep{selfrefine2023,reflexion2023}, atop generic edits and reference-guided minimal-hunk transplant, with every patch independently test-validated and abstentions escalated.
\item \textbf{An empirical result on the baseline's own corpus and metric,} with mechanism attribution, a framework-only ablation isolating the LLM layer, and agreement across two commodity builders.
\item \textbf{Artifacts.} Harness, import pipeline, prompts, synthesized repairers, per-submission logs, and all raw model outputs.\footnote{Anonymized repository submitted as supplementary material.}
\end{itemize}

\subsection{Problem Formulation}
An \emph{assignment} is a triple $A = (d, T, R)$: a natural-language description $d$, a test suite $T = \{(x_i, y_i)\}$ (function-entry or judge-style stdin/stdout), and the pool $R$ of correct student solutions, which the setting assumes is available at feedback time, as every per-assignment system from CLARA to Refactory does \citep{clara2018,refactory2019}. A \emph{repair} of a buggy submission $b$ is a program $p$ that passes all of $T$. Patch quality is measured, never gated: RPS, the tree-edit distance between the ASTs of $b$ and $p$ normalized by the size of $b$, following Refactory's definition \citep{refactory2019}, is reported for every repair, since a small patch is feedback on the \emph{student's} program while a rewrite passes tests but teaches nothing \citep{itsp2017}.

Conventional LLM-based APR maps each $b$ to a query $\mathrm{LLM}(d, T, b)$. \textsc{CoEP} instead synthesizes, once per assignment, a \emph{repairer} $\rho_A : b \mapsto p \,\cup\, \{\bot\}$, an ordinary module with no model access, and deploys the hybrid: $\mathrm{repair}(b) = \rho_A(b)$ if $\rho_A(b) \ne \bot$ (local, ${\approx}0$ marginal cost), else $\mathrm{LLM}(d, T, b, r)$: the conventional call, strengthened with one reference $r$ chosen to match the student's strategy by clustering $R$ on program structure and drawing $r$ from the cluster nearest $b$.

\subsection{Repairer Synthesis (once per assignment)}
\textbf{Build-set selection (local, no LLM cost).} The builder does not see the whole pool; it sees a \emph{chosen} sample. We cluster the buggy pool on a structural view (TF-IDF over normalized-AST paths, identifiers folded) and, walking clusters largest-first, take from each the member with the smallest tree-edit distance to its nearest correct solution, a clean single-misconception exemplar rather than the medoid's typical but tangled program, paired with that nearest correct program. The result is a set of worked (buggy $\to$ fixed) pairs: frequent misconceptions first, each shown \emph{with} its minimal fix, so a weak builder needs only to generalize a transformation it is shown, not infer it.

\textbf{Rule authoring.} The builder LLM receives $d$, $T$, reference solutions (structural-cluster medoids of $R$), and the worked pairs, and emits the assignment-specific rule module: AST rewrite rules, each named after the misconception it targets and tagged with the failure symptoms it addresses. The contract is strict. A rule locates its edit on the AST and splices it as a source-span replacement, never re-rendering the module, which would reformat untouched lines. It emits candidates rather than claimed fixes, and it never rewrites a whole function: a rule that cannot express a targeted edit must abstain so the submission escalates.

\textbf{Generate--validate--refine.} A single-shot module can contain its own defects, so the harness closes the loop: it loads the module, runs it on the sample bugs, \emph{independently} validates every candidate patch by executing the full suite (the repairer's own claims are never trusted), and, while any sample remains unrepaired, returns the module with per-bug outcomes and the still-failing sources for revision, up to $R_{\max}{=}3$ builder calls. The best-validated round is kept, and build cost is exactly the token count of these exchanges, measured from the raw strings.

\subsection{Local Repair (every submission)}
The frozen tool repairs in three stages, cheapest and smallest-patch first, validating every candidate against the full suite before it is kept:

\textbf{(1) Named rules + generic search.} Rules are \emph{candidate generators} composed by a symptom-ordered search: the failing-test signature ranks rules whose declared symptoms match, and each depth of composition is tested before the next is enumerated, so the shallowest repair is returned by construction. A shared generic library of comparison flips, off-by-one range and index shifts, and Boolean-operator flips is always on, covering common slips regardless of what the builder wrote; it inverts the classical mutation-operator space \citep{mutants2014,par2013,tbar2019}. Every surviving patch carries the ordered rule names behind it, provenance that aggregates into a per-class \emph{misconception profile}.

\textbf{(2) Reference-guided minimal-hunk transplant.} Most student bugs need a structural edit no token-level rule expresses; the correct pool supplies it. We diff $b$ against its structurally nearest correct solutions, rename the reference's variables to the student's (parameters by position, locals by first-appearance order), and adopt the \emph{smallest} set of differing line-hunks that passes the tests, candidates ordered smallest-first and batch-validated, returning the minimum-RPS passer. This is reference reuse in the lineage of CLARA, Sarfgen, and Refactory \citep{clara2018,sarfgen2018,refactory2019}, at hunk granularity rather than block granularity, which is what keeps patches smaller than the hand-built tool's.

\textbf{(3) Escalation.} A submission both stages abstain on takes the fallback $\mathrm{LLM}(d,T,b,r)$, its cost counted against \textsc{CoEP} in every comparison. Abstention is not the only trigger. Local repair's acceptance test is the instructor's suite, which says nothing about patch size, so transplant can return a patch larger than the student's whole program while the rule layer must abstain whenever it cannot express a targeted edit. We give transplant the same contract by escalating any passing local patch whose $\mathrm{RPS}$ exceeds $1$: a patch at least as large as the program it repairs is a rewrite, not a repair, under any assignment's standards. The smaller of the local and model patches is kept, so escalating can cost a call but never coverage or patch size.

The threshold is a constant rather than a calibrated quantity, and that is a finding: across 38 candidate rules --- relative, quantile, and constant --- repair rate is unchanged and every setting beats all three baselines on all four metrics, so we take the one whose value is a definition rather than a fitted number and report the rest as a sensitivity band (RQ5).

\textbf{(4) Self-learning.} Each successful fallback fix can be generalized by the LLM into a new named rule, kept only if the augmented tool then repairs that miss on its own. Absorption writes to a staging copy the evaluated pass never consults, so no submission's outcome depends on which preceded it, and the accumulated rules are a separate artifact evaluated by a second frozen pass and priced to themselves (Section~\ref{sec:setup}). It spends calls only on submissions that already escalated, so it too leaves the build claim untouched.

The local path runs on a CPU in ${\sim}1$--$2$\,s per submission, deterministically and offline; a defective tool degrades to $\bot$, never to a wrong ``repair'', because the harness re-validates every patch before a student sees it.

\section{Related Work}
\label{sec:related}

\textbf{APR for programming assignments.} The pre-LLM systems \citep{itsp2017,clara2018,sarfgen2018,refactory2019,verifix2022} exploit per-assignment structure, and the reference-reuse ones depend on finding a structurally matching correct solution; our transplant stands in that lineage at hunk rather than block granularity and exceeds the strongest of them on both coverage and patch size. Closest to our synthesis layer, Refazer learns per-assignment transformations from (buggy, fixed) pairs with PROSE \citep{refazer2017}; \textsc{CoEP} replaces the example-driven synthesizer with a cheapest-tier LLM that \emph{names} the misconception behind each rule, and surrounds it with generic search, transplant, and harness-gated escalation.

\textbf{LLM-based repair.} Repair-as-generation \citep{alpharepair2022}, conversational test feedback \citep{chatrepair2024}, student-program repair \citep{pydex2024,mmapr2022}, faster per-query inference \citep{fastfixer2024}, a tutor in the loop \citep{cref2024}, counterexample-guided minimal repair \citep{orvalho2025} and retrieval-guided learner-tailored repair \citep{dai2026} are all per-submission, and complementary --- any can serve as \textsc{CoEP}'s fallback --- but \textsc{CoEP} shifts the primary cost to the assignment.

\textbf{Templates and tool synthesis.} Fixed libraries of human-curated fix templates repair a surprising share of real bugs \citep{par2013,tbar2019}; \textsc{CoEP}'s generic layer inverts the mutation-operator space \citep{mutants2014} and its novelty is the \emph{synthesized, assignment-specific} layer. Cascades, cheap pipelines and caching \citep{frugalgpt2024,srepair2024,anthropiccaching,openaicaching} optimize \emph{within} pay-per-query, and agent tool-making amortizes written code across episodes \citep{voyager2024,toolmakers2024,selfrefine2023,reflexion2023}. \textsc{CoEP} removes queries instead.

\smallskip\noindent\textbf{Ethical statement.} \textsc{CoEP} automates feedback, not grading; unhandled submissions take the full-LLM path; repairs are auditable and the data public.

\section{Experiments}

\subsubsection{Research Questions.}
\begin{itemize}\itemsep2pt \parskip0pt
\item \textbf{RQ1}: Assignment by assignment, how many submissions does \textsc{CoEP} repair, and how much of each program does it edit?
\item \textbf{RQ2}: How much does the once-per-assignment structure reduce turnaround and dollars, past what enrollment does the build pay off, and can caching or cheaper tiers close the gap?
\item \textbf{RQ3}: What produces the repairs, and what does the LLM-authored layer add over the symbolic substrate?
\item \textbf{RQ4}: Do rules induced from \textsc{CoEP}'s own escalations improve the frozen tool on submissions they were not induced from?
\item \textbf{RQ5}: Does the advantage hold across assignment difficulty, LLM provider, and the escalation threshold?
\end{itemize}

\subsubsection{Baselines.}
\label{sec:setup}
\textbf{Refactory} \citep{refactory2019} is the classical symbolic per-assignment tool: it refactors the class's correct solutions to match each buggy program's structure and transplants the divergent blocks. On its own corpus we use its published results; on Codeforces we run the released tool in its strongest configuration. \textbf{PyDex} \citep{pydex2024} is per-submission LLM repair: each buggy submission is sent to the model in its few-shot layout, which prepends the three most similar (buggy, correct) exemplars retrieved from the class pool, sampled candidates are filtered by the test oracle, and the surviving candidate closest to the student's program is returned. \textbf{PyDex\textsubscript{PC}} re-prices the same queries under provider prompt caching, as an upper bound that assumes a cache hit wherever the provider's rules allow one. \textbf{\textsc{CoEP}} is ours, synthesized once per assignment and builder and evaluated in three configurations. \textbf{\textsc{CoEP}\textsubscript{L}} runs the frozen local tool alone with zero deployment LLM use and accepts any patch its test oracle passes --- deliberately the same acceptance rule Refactory uses, so the comparison is about repair rather than a size filter one side applies. \textbf{\textsc{CoEP}\textsubscript{LF}} adds the per-submission fallback, spent on abstentions and on passing local patches above $\mathrm{RPS}=1$. \textbf{\textsc{CoEP}\textsubscript{L+SL}} is \textsc{CoEP}\textsubscript{L} re-run with the self-learned rules merged and frozen beforehand, so the arm is order-independent; its induction calls are priced to it, and the few submissions a rule was induced from are reported separately.

\subsubsection{Datasets.}
We evaluate on 11 problems and \NumEval{} buggy submissions drawn from two real-student corpora: five CS1 assignments contributing \NumEvalRefac{} buggy and 2{,}442 correct programs at 7.4 tests and 11.9 lines each, and six Codeforces problems contributing \NumEvalCF{} buggy and 698 correct at 35.5 tests and 12.3 lines. Refactory contributes five CS1-level assignments \citep{refactory2019}, the standard corpus of this literature \citep{verifix2022,pydex2024,orvalho2025}. Codeforces contributes six competitive-programming problems from the open-r1 release \citep{penedo2025codeforces}, spanning difficulty ratings from 800 to 2000, which cover five official rating bands from Newbie to Candidate Master \citep{cfratings}; we keep only problems whose complete official test suites are released, so the oracle is the judge's own. Every submission each corpus labels buggy is a repair target for every arm, so the denominator is the pool as published and is identical across arms. No train/test split is used, as prior per-assignment systems assume, and all results additionally hold with \textsc{CoEP}'s build samples excluded from the denominator.

\subsubsection{LLM Configuration.}
Every LLM arm runs on two models, one per provider: \textbf{GPT-5.4-mini} (\$0.75/\$4.50 per Mtok) and \textbf{Claude Sonnet 5} (\$2/\$10 per Mtok). We select each provider's cheapest tier at which prompt caching is functional, in fairness to the caching baseline: PyDex\textsubscript{PC} only competes if caching can engage, and we verified that the absolute cheapest tiers rule it out --- Haiku 4.5 refuses to cache below its 4{,}096-token minimum, above these prompts, and GPT-5.4-nano's automatic caching did not engage on identical 1{,}200-token prompts, whereas both selected models cache at their documented 1{,}024-token minimums. Cheap tiers also keep every measured dollar gap a conservative floor.

\subsubsection{Evaluation Metrics.}
\textbf{Repair rate (RR)} is the percentage of buggy submissions for which a system produces a program passing the full test suite. \textbf{Relative patch size (RPS)} is the tree-edit distance between buggy and repaired ASTs normalized by buggy program size, reimplemented from Refactory's definition \citep{refactory2019}; smaller patches preserve the student's approach and are pedagogically preferable. RPS never \emph{claims} a repair the tests do not support --- it enters the pipeline only in \textsc{CoEP}\textsubscript{LF}, where a value above 1 routes a submission to the fallback and the smaller patch is kept, so the gate can add a call but cannot manufacture a repair or enlarge a patch.

\textbf{Average turnaround time (ATT)} is mean wall-clock seconds per submission, split into $\mathrm{ATT}_{\mathrm{cpu}}$ (local search) and $\mathrm{ATT}_{\mathrm{api}}$ (model latency); a system's one-off build wall-clock is an intercept and is reported per assignment. \textbf{API cost} is USD of inference over the whole benchmark, including that build, priced at the tiers above from exact token counts. The \textbf{escalation rate} $f$, the fraction of submissions taking a model call, is what the break-even $N^{*}=C_{\text{build}}/(\Delta(1-f))$ consumes.

Repair rates carry 95\% Wilson intervals, and comparisons between arms we ran ourselves are paired by submission and tested with exact McNemar --- exact rather than chi-square because the discordant counts are often single-digit. The one exception is Refactory on its own corpus, where we quote published per-assignment results and have no per-submission outcomes to pair; that comparison is marked unpaired wherever it appears.

\subsubsection{Setup.}
All experiments run on one Apple M1 Ultra workstation (64\,GB RAM) under Python\,3.13, CPU only but for the API calls, and evaluations run without concurrency so ATT is a measurement rather than a contention artifact. PyDex uses $K{=}10$ sampled candidates per submission, every call billed and timed. \textsc{CoEP}\textsubscript{L} and \textsc{CoEP}\textsubscript{LF} come from a single pass with no duplicated calls. Refactory runs with its original algorithm unchanged, ported to Python\,3.

The central finding is \textsc{CoEP}'s local repair against the strongest non-LLM tool. On the Refactory corpus of \NumEvalRefac{} submissions it repairs \textbf{\LocalRR\%} at mean \textbf{\LocalRPS} RPS against Refactory's published \textbf{\RefacRR\%} at \textbf{\RefacRPS} --- higher coverage and a patch a quarter smaller, at zero marginal LLM cost. That comparison is unpaired, since Refactory's own-corpus results are published aggregates; where we run it ourselves, on Codeforces, the gap widens and the test is paired: \LocalRRCF\% against \RefacRRCF\%, exact McNemar $b{=}406$, $c{=}17$, $p{<}10^{-97}$. A synthesized tool is not merely cheaper than a symbolic one that consumes every correct solution; it repairs more.

Against per-submission LLM repair the separation is not coverage. \textsc{CoEP}\textsubscript{L} reaches \LocalRRAll\% and PyDex \PydexRRAll, and the paired test finds no difference ($b{=}28$, $c{=}25$, $p{=}0.78$): on CS1-scale programs coverage is near-saturated for any competent repairer \citep{pydex2024}. The separation is \emph{patch size}, \LocalRPSAll{} against \PydexRPSAll. Adding the escalation tail takes \textsc{CoEP}\textsubscript{LF} to \textbf{\HybridRRAll\%} at \textbf{\HybridRPSAll}, now ahead on coverage too ($b{=}28$, $c{=}7$, $p{=}5.1{\times}10^{-4}$; Wilson $[99.38, 99.82]$ against $[98.52, 99.26]$). Every patch is test-validated before a student sees it, so the only local failure mode is abstention, never a wrong repair, and abstentions take the LLM path.

Table~\ref{tab:effect} is per-assignment because corpus means hide two things. Refactory's rate swings from 40.3\% to 100\% while neither LLM arm drops below 93.8\%, and the swing does not track difficulty --- it repairs all of the rating-2000 problem and four in ten of a rating-1600 one (RQ5). And a low patch size is not always a virtue: Refactory's \RefacRPSCF{} on Codeforces looks competitive against \HybridRPSCF, but is averaged over the \RefacRRCF\% it accepts where \textsc{CoEP}\textsubscript{LF} repairs \HybridRRCF\%.

Against per-submission LLM repair, coverage is at parity ($p{=}0.78$) and patch size is a third smaller; escalation adds \HybridRRAll\% coverage, ahead of PyDex at $p{<}10^{-3}$.}}

\subsubsection{RQ2: Cost Effectiveness and Break-Even}

\begin{figure}[t]
\centering
\includegraphics[width=\columnwidth]{figures/fig_cost.pdf}
\caption{Where amortization overtakes per-submission inference. Ticks mark the
eleven assignments' sizes; ten clear $N^{*}$.}
\label{fig:cost}
\end{figure}

The systems differ in \emph{cost structure}, not just constant. A per-submission arm pays an inference on every submission, so its cost grows with enrollment and recurs every term; \textsc{CoEP} pays a one-off $C_{\text{build}}$ per assignment, repairs the covered fraction at \emph{zero} marginal LLM cost, and pays per submission only on the escalating tail. Over the benchmark that is \$\HybridUsd{} against PyDex's \$\PydexUsd{} at the frontier tier (\CostRatio$\times$) and \$\HybridUsdMini{} against \$\PydexUsdMini{} at the cheap one (\CostRatioMini$\times$); of our total, \$\BuildUsdSonnet{} is the build and \$\GateUsd{} the entire deployment spend across \NumEval{} submissions.

Fig.~\ref{fig:cost} turns that into the quantity a department decides on. With $\Delta$ the marginal per-submission saving and $f$ the escalation rate, synthesis wins past $N^{*}=C_{\text{build}}/(\Delta(1-f))$, which our measured build and tail put at \textbf{11 submissions per assignment} against PyDex and 13 against PyDex\textsubscript{PC}. Ten of eleven assignments exceed it, most by an order of magnitude. Below $N^{*}$ a per-query repairer is the right tool, and we claim nothing else.

\textbf{Caching and cheaper tiers do not close it.} PyDex\textsubscript{PC} re-prices every query under the provider's documented caching rules, as an upper bound assuming a hit wherever one is allowed, and every LLM arm already runs at the cheapest tier at which caching functions. The discount is \CacheSavingFrac\% (\$\PydexUsd{} to \$\PydexPCUsd), and the measurement says why it is small: caching pays for a shared leading \emph{prefix}, and the shared material here is not a prefix. The variable buggy program and retrieved exemplars come first, leaving an identical prefix of about ten tokens; what remains is reuse within one submission across its $K$ candidates. Analytically, $N^{*}$ is invariant to token price when build and per-query tokens bill on the same schedule, since $C_{\text{build}}$ and $\Delta$ scale together. The claim is about how many calls per specification are made, not their price --- and since every arm runs at the cheapest tier, the measured gaps are a \emph{floor}.

\textbf{Turnaround is a trade, not a sweep.} At the frontier tier \textsc{CoEP}\textsubscript{LF} answers in \HybridATT\,s against \PydexATT\,s, and the split is the story: we spend \LocalATT\,s on local CPU search and API on a tenth of submissions, PyDex 0.66\,s locally and 13.97\,s on the network. At the cheap tier the ordering reverses (\PydexATTMini\,s against \HybridATTMini\,s), because a small model returns one completion faster than our search enumerates and re-executes candidates; we report it rather than quoting only the flattering tier. What the seconds buy is an answer that is deterministic, rate-limit-free, never leaves the institution, and is unaffected by the deadline-night spikes that make a hosted queue slowest when a class most needs it.

\smallskip
\noindent\fbox{\parbox{0.965\columnwidth}{\textbf{RQ2.} \textsc{CoEP} replaces a per-submission inference with a one-off \$\BuildUsdSonnet{} synthesis plus a \$\GateUsd{} tail, \CostRatio$\times$ cheaper over \NumEval{} submissions and breaking even at $N^{*}{=}11$ per assignment. Caching recovers only \CacheSavingFrac\% and $N^{*}$ is price-invariant, so the gap is structural.}}

\subsubsection{RQ3: Where the Repairs Come From}

\textbf{Two complementary local mechanisms.} Named rules make small, labelled edits for common misconceptions --- a relaxed comparison, an off-by-one bound --- and are surgical, at \RuleShare\% of repaired submissions and mean RPS \RuleRPS{} (Table~\ref{tab:source}). Most student bugs are not single-token slips; they need a structural edit no token-level rule expresses, and the transplant supplies it by adopting the smallest set of differing hunks from a structurally-matched correct program, disturbing five times more of the student's code. The transplant lifts a rule-only tool to competitive coverage; the rules keep common cases near-minimal and are the only layer leaving a diagnosis behind. The division is not uniform (Fig.~\ref{fig:source}): where the pool is deep the transplant dominates, but where one misconception dominates a class the authored layer takes over --- on C4 a single rule, \texttt{carry\_fix\_two\_value\_print}, repairs 27 of 38 submissions.

\subsubsection{RQ4: Learning From Its Own Escalations}

\textsc{CoEP}\textsubscript{L+SL} is the frozen tool re-run with the rules absorbed from its own fallback fixes. Absorption happens outside the evaluated pass and the augmented tool is frozen before this arm runs, so the comparison against \textsc{CoEP}\textsubscript{L} is order-independent: the same submissions, the same acceptance rule, two rule sets. Absorption learns only from submissions the local tool fails outright, never from threshold escalations, so its supply of material is exactly the abstention set.

\textbf{The first result is how little there is to learn from.} Across the 22 (assignment, builder) cells the frozen tool abstains on 28 submissions and 19 cells leave nothing to absorb --- not a failure of the mechanism but what a 99.06\% local repair rate means. Where it does abstain, absorption fires: four rules on R2 with the frontier builder, three on R2 with the cheap one, one on C3.

\textbf{Where it fires, the rules transfer.} R2 moves from 93.79\% to \textbf{95.40\%} on the four, and to \textbf{96.55\%} on the cheap builder's three; on C3 a single rule, \texttt{binarysearch\_zero\_exit}, closes the last gap to 100\%. Paired, both are significant: $b{=}9$, $c{=}1$, $p{=}0.021$ at the frontier tier and $b{=}12$, $c{=}0$, $p{=}4.9{\times}10^{-4}$ at the cheap one. The cheap builder learning \emph{more} is worth stating --- the material is the same 27 abstentions, and what differs is how general a rule the model writes from one fix. Eight submissions induced these rules out of 504 evaluated, so the gain is measured almost entirely on programs the rules were never validated against, for \$0.76 of induction priced to the artifact. The names again read as misconceptions: \texttt{uniqueness\_count\_gt1\_to\_neq1}, \texttt{counter\_var\_confusion}.

\smallskip
\noindent\fbox{\parbox{0.965\columnwidth}{\textbf{RQ4.} Absorption fires on 3 of 22 cells; on the other 19 the frozen tool leaves no miss to learn from. Where it fires the rules generalize --- R2 to 95.40\% (frontier) and 96.55\% (cheap), C3 to 100\%, for \$0.76 --- significant at $p{=}0.021$ and $p{<}10^{-3}$ on submissions they were not induced from.}}

\subsubsection{RQ5: What the Conclusion Survives}

\textbf{Difficulty.} As the six Codeforces problems climb from rating 800 to 2000 the deep CS1 solution pools give way to sparser ones, and the symbolic baseline tracks that: 90.8\% on CS1, 83.1\% on the 800--1000 band, \textbf{54.3\%} on 1200--2000, against \textsc{CoEP}\textsubscript{LF}'s 99.4/100.0/100.0. But the per-assignment rows say difficulty is not the driver. Refactory repairs all of C6 (rating 2000) and four in ten of C5 (rating 1600); its rate is not monotone in rating. What predicts the collapse is whether the pool holds a structurally matching reference, since block-level reuse starves when strategies diverge --- C5's 77 submissions draw on a pool of two correct solutions. Every arm's RPS roughly doubles from CS1 to the hard band, so the ordering survives while the absolute numbers do not.

\textbf{Provider.} \textsc{CoEP}\textsubscript{LF} reaches 99.7\% at 0.398 RPS with the frontier builder and 99.7\% at 0.411 with the cheap one --- 3\% in patch size for an 18-fold difference in build price (\$\BuildUsdSonnet{} against \$\BuildUsdMini) --- with the ordering against both baselines identical either way.

\textbf{Threshold.} We swept 38 candidate rules --- median- or mean-anchored with MAD, standard-deviation or interquartile spread, bare quantiles, multiples of the assignment's median, corpus-wide variants, and constants --- of which 29 give distinct settings inside the cached escalation prefix and are measured exactly. Three things hold across all. Repair rate is \emph{identical} to four decimals at 99.66\%, because the gate re-examines only patches the tests already passed and keeps the smaller. Mean RPS falls monotonically with the escalation rate, 0.451 to 0.378, with no interior optimum, so the setting is a budget rather than a value to discover. And total spend stays within \$12.47--\$15.61, so every one of the 29 beats all three baselines on repair rate, patch size, turnaround and dollars at once.

Two findings inside the sweep are negative. Making the threshold \emph{relative to the assignment} does not pay --- a single corpus-wide cutoff sits on the same frontier or better, since RPS is already normalized by program size and normalizing again directs calls to assignments the tool already handles --- and the median-plus-MAD family we began with is Pareto-dominated. We therefore ship the setting whose value is a definition rather than a fitted constant, at the honest cost of being nearly inert where local patches are uniformly small: it fires on 0.0\% of R3 against 22.3\% of C2.

\smallskip
\noindent\fbox{\parbox{0.965\columnwidth}{\textbf{RQ5.} Yes on all three. The symbolic baseline falls 90.8\% to 54.3\% between the CS1 corpus and the hardest Codeforces band while \textsc{CoEP}\textsubscript{LF} holds 100\%; the builders agree to 3\% in patch size for an 18-fold price difference; and across 29 thresholds the repair rate is invariant while patch size spans 0.378--0.451 and spend \$12.47--\$15.61, so every setting beats every baseline on all four metrics.}}
