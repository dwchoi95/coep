\begin{abstract}
Large language models (LLMs) repair buggy submissions to programming assignments well, but they are deployed \emph{one query per submission}: every request re-transmits the same assignment description and test suite, so cost grows linearly with enrollment and recurs every term, while caching and cheaper models shrink only the constant, not the structure.
Observing that assignment repair is a \emph{many-instances, one-specification} regime, we propose \textsc{CoEP}, a framework that shifts LLM investment from the submission to the assignment.
An LLM agent reads the specification, tests, and a few sample programs once, and synthesizes an executable symbolic repairer---problem-specific AST rewrite rules over a generic bounded edit search---whose every patch is independently test-validated and size-capped.
Refined through validation feedback and then deployed locally, the repairer fixes subsequent submissions at zero marginal LLM cost, escalating the rest to conventional per-submission repair so that coverage is never sacrificed; it is also a transparent artifact that instructors can audit, produces minimal patches by construction, and runs in milliseconds.
Experiments on real student programs, against per-submission LLM repair, a symbolic non-LLM tool, and cost-reduction alternatives such as caching and model cascades, show that amortizing LLM reasoning into a verifiable per-assignment artifact preserves repair quality while fundamentally improving the cost structure of serving many instances of one specification.
\end{abstract}

\section{Introduction}

Timely, individualized feedback is the scarcest resource in programming education.
Introductory courses routinely enroll hundreds of students on campus and tens of thousands online, each producing a stream of buggy submissions that instructors cannot examine one by one.
Automated program repair (APR) has therefore long been proposed as a feedback engine for programming assignments: given a buggy student submission and the assignment's test suite, produce a small patch that makes the submission correct while preserving the student's own approach \citep{itsp2017,clara2018,sarfgen2018,refactory2019,verifix2022}.

Large language models (LLMs) have made this vision practical.
LLM-based repair now fixes the large majority of real student programs---up to 96.5\% of buggy Python submissions in PyDex \citep{pydex2024}---and general-purpose LLM repair systems report strong results at modest per-bug prices \citep{chatrepair2024,alpharepair2022,fastfixer2024,cref2024}.
But these systems all share a deployment paradigm that we argue is mismatched with the economics of the classroom: \emph{every buggy submission triggers a fresh LLM query} that re-transmits the assignment description, the test suite, and formatting instructions before the model ever sees the student's code.
In the benchmark we study, 93\% of the input tokens of a per-submission repair prompt are byte-identical across all submissions to the same assignment (\PrefixFrac\% in a contiguous cacheable prefix); the submission itself is 8\% of what the course pays to process, query after query, semester after semester.
Provider-side prompt caching \citep{anthropiccaching,openaicaching} discounts the redundant prefix but does not change the paradigm: in our measurements it removes \CacheSavingFrac\% of the per-submission cost, and every submission still requires a round trip to a frontier model, with the attendant marginal cost, latency, rate limits, and dependence on an external service.

Our key observation is that assignment repair is a \emph{many-instances, one-specification} regime.
A single assignment is attempted by hundreds or thousands of students whose failures cluster into a modest number of recurring misconceptions \citep{clara2018,refactory2019}.
Pre-LLM assignment-repair systems exploited exactly this structure---CLARA clustered correct solutions, Refactory refactored them into a per-problem search space---achieving cheap per-submission repair, but at the cost of hand-built machinery or large pools of prior correct solutions.
Per-submission LLM repair inverts the trade-off: it is automatic and general, but pays for the same specification-level reasoning on every single query.

We propose to get both halves: \textbf{spend the LLM once per assignment, not once per submission}.
In \textsc{CoEP} (\underline{Co}st-\underline{E}ffective \underline{P}rogram repair), an LLM agent receives the assignment specification, test suite, a few reference solutions, and a handful of historical buggy submissions, and \emph{writes a program repairer}: a deterministic Python module combining problem-specific rewrite rules with a generic edit-search library, validating every candidate against the visible tests under a patch-size cap.
After at most three harness-driven refinement rounds it is frozen and deployed: submissions are repaired \emph{locally}, in milliseconds to seconds, at zero marginal LLM cost, and any the repairer cannot fix escalate to the conventional LLM path---so the hybrid never does worse than the paradigm it replaces.

On a benchmark of \NumProblems{} introductory Python assignments with \NumBuggy{} buggy programs (misconception-crafted and mutation-generated), holding the underlying LLM fixed across all conditions, \textsc{CoEP}'s synthesized repairers alone fix \CoepRate\% of \NumEval{} held-out submissions; with LLM fallback the hybrid fixes \HybridRate\%---exactly matching the per-submission frontier-LLM baseline in both repair rate and patch quality, with minimality now guaranteed by a validator rather than requested in a prompt.
The one-off synthesis cost of \$\BuildUsdPerProblem{} per assignment is recouped after $\approx$\BreakEvenN{} repaired submissions against the frontier baseline, and thereafter each repair costs \AsymReduction$\times$ less---a gap caching cannot close, because \FallbackRate\% is the only fraction of traffic that touches a model at all.
Against the stronger zero-build competitors this observation invites---a FrugalGPT-style cheap-model cascade, and our generic edit search with no synthesis---synthesis dominates beyond a few hundred submissions per assignment, and composed with the cascade as its fallback, \textsc{CoEP} repairs 100\% of submissions at one tenth the frontier baseline's marginal cost.

This paper makes the following contributions:
\begin{itemize}
\item \textbf{A new deployment paradigm for assignment repair.} We identify the many-instances, one-specification structure of programming-assignment APR and formulate \emph{per-assignment repairer synthesis}: amortizing LLM reasoning into a reusable, locally executable repair artifact, with a cost model and break-even analysis for when it pays off.
\item \textbf{The \textsc{CoEP} system.} A builder agent that synthesizes per-assignment repairers through a generate--validate--refine loop \citep{selfrefine2023,reflexion2023} over a repair-operator library; repairers are independently re-validated (test-suite pass + relative-patch-size cap) so a repairer can never self-report success, and are backed by hybrid LLM escalation.
\item \textbf{A controlled, contamination-free evaluation.} A new benchmark of \NumProblems{} assignments / \NumBuggy{} buggy programs built from a misconception taxonomy plus seeded mutation \citep{mutants2014}, with both repair paradigms driven by the \emph{same} frontier model, exact token-level cost accounting, statistical tests, and four cost baselines (per-submission, cached, cheap-model cascade, generic-search-only); plus ablations isolating the contribution of synthesized rules, refinement rounds, and builder-model capability.
\item \textbf{Artifacts.} We release the benchmark, harness, prompts, synthesized repairers, and all raw model outputs.\footnote{Anonymized repository submitted as supplementary material.}
\end{itemize}

Three consequences follow.
(1)~\emph{Caching is a discount, not a fix.} Prompt caching bills the shared prefix at $0.1\times$ after a $1.25\times$ write \citep{anthropiccaching}, cutting per-submission cost from \$$\BaseUsdPerInst\times10^{-3}$ to \$$\CachedUsdPerInst\times10^{-3}$ in our setting (-\CacheSavingFrac\%)---but the submission-dependent tokens, all output tokens, and one frontier-model inference per submission remain.
(2)~\emph{Costs scale with enrollment, not with assignments.} A department running 40 course sections, each with hundreds of buggy submissions per assignment, pays per student-attempt; the specification-level reasoning it is paying for is identical every time.
(3)~\emph{The redundancy is exactly the amortizable part.} What is constant per assignment---understanding the specification, the tests, and the space of likely mistakes---can be reified \emph{once} into an executable artifact. That is the move \textsc{CoEP} makes, and the rest of the paper quantifies what it buys.

\subsection{Problem Formulation}
An \emph{assignment} is a triple $A = (d, T, R)$: a natural-language description $d$, a visible test suite $T = \{(x_i, y_i)\}$ over a designated entry function, and a small set $R$ of reference solutions.
A \emph{repair} of a buggy submission $b$ is a program $p$ such that (i)~$p$ passes all of $T$ and (ii)~$\mathrm{RPS}(b,p) \le \tau$, where RPS is the token-level relative patch size---the Levenshtein distance between the lexical token sequences of $b$ and $p$, normalized by $|b|$---following the patch-size metrics of Refactory and PyDex \citep{refactory2019,pydex2024}.
The cap $\tau$ (we use $\tau = 0.35$) operationalizes the pedagogical requirement that a repair be feedback on the \emph{student's} program: it rules out replacing the submission with a reference solution, which passes tests but teaches nothing \citep{itsp2017}.

Conventional LLM-based APR maps each $b$ to a query $\mathrm{LLM}(d, T, b)$.
\textsc{CoEP} instead synthesizes, once per assignment, a \emph{repairer} $\rho_A : b \mapsto p \,\cup\, \{\bot\}$---an ordinary Python module with no model access---and deploys the hybrid
\[
\mathrm{repair}(b) =
\begin{cases}
\rho_A(b) & \text{if } \rho_A(b) \ne \bot \;(\approx 0\text{ cost})\\
\mathrm{LLM}(d, T, b) & \text{otherwise.}
\end{cases}
\]

\subsection{Repairer Synthesis}
A builder agent receives $d$, $T$, $R$, and $k{=}5$ historical buggy submissions $B_{\mathrm{build}}$, together with the documentation of a small \emph{repair-operator library} that we provide as the substrate for all synthesized repairers.
The library contributes three reusable capabilities:

\textbf{(1) Generic edit search.} \texttt{candidates\_generic} enumerates candidate patches by applying small semantic edits at every applicable AST site---comparison/arithmetic/Boolean operator swaps, integer off-by-one shifts, Boolean-constant flips, index shifts, and argument swaps---singly or in pairs. This is the inversion of the classical mutation-operator space \citep{mutants2014} and plays the role that hand-curated fix templates play in template-based APR \citep{par2013,tbar2019}.

\textbf{(2) Test-driven validation.} \texttt{first\_passing} runs candidates against the full suite $T$ in a sandbox and returns the first candidate that passes \emph{all} tests while satisfying the RPS cap. Synthesized code is contractually forbidden from returning an unvalidated patch.

\textbf{(3) Failure diagnosis.} \texttt{failing\_tests} exposes the failing-test pattern of the input program, letting repairers dispatch: e.g., a \texttt{flatten} submission whose output is correct but reversed selects stack-order rules before anything else.

The builder's essential creative work is the \emph{problem-specific rule set}: AST rewrite rules that anticipate the misconceptions students exhibit for \emph{this} assignment---wrong recursion base cases for \texttt{fibonacci}, count-only bracket matching for \texttt{balanced\_brackets}, order-destroying \texttt{set()} deduplication for \texttt{unique\_in\_order}---derived by studying $d$, $T$, $R$, and $B_{\mathrm{build}}$.
These rules generate edits far outside the generic operator space (inserting a missing \texttt{else} branch, wrapping a loop body in a recursive call), and our ablation shows they, not the generic search, carry the paradigm (RQ3).

\begin{algorithm}[t]
\caption{Per-assignment repairer synthesis}
\label{alg:builder}
\begin{algorithmic}[1]
\REQUIRE assignment $(d,T,R)$, sample bugs $B_{\mathrm{build}}$, rounds $R_{\max}$
\STATE $\rho \leftarrow \mathrm{LLM}_{\mathrm{build}}(d, T, R, B_{\mathrm{build}}, \mathrm{lib})$ \hfill$\triangleright$ single shot
\FOR{$r = 2 \dots R_{\max}$}
  \STATE $F \leftarrow \{(b,\mathrm{outcome}(\rho,b)) : b \in B_{\mathrm{build}}\}$ \hfill$\triangleright$ harness
  \IF{all outcomes are \textsc{repaired}} \RETURN $\rho$ \ENDIF
  \STATE $\rho \leftarrow \mathrm{LLM}_{\mathrm{refine}}(\rho, F)$ \hfill$\triangleright$ single shot
\ENDFOR
\RETURN $\rho$
\end{algorithmic}
\end{algorithm}

\textbf{Generate--validate--refine.}
Because a single-shot synthesized module can contain its own defects, the harness closes the loop (Algorithm~\ref{alg:builder}): it installs the module, applies it to $B_{\mathrm{build}}$, \emph{independently} re-validates every returned patch (sandboxed test execution plus RPS check---the repairer's own claims are never trusted), and, if any sample bug is unrepaired, sends the module back with per-bug outcomes and the failing submissions for revision, up to $R_{\max}{=}3$ total rounds.
This is a deliberately austere instantiation of self-refinement \citep{selfrefine2023,reflexion2023}: every LLM interaction is a single prompt--response pair, so the entire build cost is the token count of at most $2R_{\max}$ message payloads, measured exactly.

\textbf{Deployment.}
The frozen repairer runs in a subprocess with a wall-clock budget (60s; observed mean \CoepMeanSec s) and no network access.
Its patches are re-validated by the grading harness before being shown to a student, so a defective repairer degrades to $\bot$ (escalation), never to a wrong ``repair.''
Escalated submissions follow the conventional per-submission LLM path; their cost is counted against \textsc{CoEP} in every comparison.

\textbf{Why synthesis, not retrieval.}
Caching past LLM \emph{patches} amortizes too, but a patch is specific to one buggy program; a synthesized rule generalizes over a misconception class, fixing submissions whose surface form was never seen.

\section{Experimental Setup}
\label{sec:setup}

We ask three research questions:
\textbf{RQ1 (Effectiveness \& quality).} How do \textsc{CoEP}'s synthesized repairers compare to per-submission frontier-LLM repair in repair rate and patch quality?
\textbf{RQ2 (Cost).} What are the token/dollar costs of both paradigms, when does repairer synthesis break even, and what is the asymptotic saving?
\textbf{RQ3 (Sources of power).} How much do the synthesized problem-specific rules and the refinement rounds contribute?

\subsection{Benchmark}
Public assignment-repair datasets (ITSP, the Refactory dataset, TutorCode) have circulated on GitHub for years and are plausibly in the training data of every current frontier model; memorization would inflate \emph{both} paradigms' repair rates and specifically contaminate the builder, which must not have seen the evaluation bugs \citep{cref2024}.
Following the data-leakage guidance for LLM evaluations in APR \citep{chatrepair2024}, we therefore constructed a fresh, \emph{memorization-safe} benchmark---no evaluation item existed before this study---while borrowing its design from established suites.
This choice trades one threat for another (the bug distribution is study-authored rather than student-authored); we disclose the construction fully here and analyze the residual threats in Discussion.

The benchmark comprises \NumProblems{} classic introductory Python assignments (digit sum, palindrome check, Fibonacci, consecutive deduplication, top-$k$ selection, sorted insertion index, bracket matching, GCD, list flattening, grade statistics), each with an assignment handout, 14 visible tests including edge cases, and three reference solutions implementing genuinely different strategies.
Each assignment has two pools of buggy programs:
\textbf{(a) Misconception-crafted} (10 per assignment): novice attempts authored for this study by LLM agents instructed with documented misconception categories---wrong base cases, off-by-one boundaries, wrong initialization, order-destroying deduplication, count-only bracket matching, single-level flattening, integer-division means---in the spirit of the qualitative bug analyses of CLARA and Refactory \citep{clara2018,refactory2019}, with required structural diversity across implementations and mechanical validation (compiles, fails $\ge$1 test, pairwise distinct).
\textbf{(b) Mutation-generated} (up to 15 per assignment): seeded first- and second-order mutants of the reference solutions under classical mutation operators, the standard proxy for real faults \citep{mutants2014} used by IntroClass, Codeflaws, and QuixBugs \citep{manybugs2015,codeflaws2017,quixbugs2017}.
Every buggy program is machine-checked to compile and fail at least one test; every reference passes all tests.
In total: \NumBuggy{} buggy programs; per assignment, 5 (2 crafted + 3 mutants) form the builder's $B_{\mathrm{build}}$ and up to 20 are held out for evaluation ($n{=}\NumEval$).
The crafted/mutant distinction doubles as an evaluation instrument: mutants lie inside the generic operator space by construction, so \emph{crafted bugs are where problem-specific reasoning must earn its keep} (RQ3).

\subsection{Baselines}
\textbf{Per-submission LLM repair} is the deployment paradigm of PyDex/MMAPR, ChatRepair, and FastFixer \citep{pydex2024,mmapr2022,chatrepair2024,fastfixer2024}: one query per submission containing the handout, the visible tests, the buggy program, and minimal-patch instructions (the strongest known configuration for student programs; PyDex reports up to 96.5\% with few-shot prompting).
We instantiate it with the \emph{same} frontier model that powers \textsc{CoEP}'s builder, so every observed difference is attributable to the paradigm, not the model.
\textbf{Cached per-submission repair} re-prices the same queries under provider prompt caching (shared prefix written once at $1.25\times$, read at $0.1\times$) \citep{anthropiccaching}.
\textbf{Cheap-model repair and cascade}: the same per-submission queries executed by a Haiku-tier model (\$1/\$5 per Mtok), alone and in a FrugalGPT-style cascade \citep{frugalgpt2024} that escalates its failures to the frontier model---the strongest \emph{zero-build-cost} competitors to amortization.
\textbf{Generic-hybrid}: our generic edit search run with no LLM synthesis at all, backed by the same frontier fallback---the strongest free local competitor, and an ablation of the synthesized rules.
We do not additionally re-run pre-LLM per-problem tools (Refactory, CLARA) as repair-rate baselines: they require dozens-to-hundreds of prior correct solutions per assignment and are consistently dominated by LLM repair on student programs \citep{pydex2024}; our contribution is orthogonal to the choice of local technique.

\subsection{Metrics}
\textbf{Repair rate}: fraction of evaluation submissions for which the system produces a program passing all visible tests \citep{refactory2019,pydex2024}. For the baseline we additionally report the \emph{quality repair rate}, counting only repairs with $\mathrm{RPS} \le 0.35$---the constraint \textsc{CoEP} enforces by construction---since a test-passing rewrite that discards the student's approach is not usable feedback \citep{itsp2017}.
\textbf{Relative patch size (RPS)}: token-level edit distance normalized by program length \citep{refactory2019,pydex2024}; smaller is pedagogically better.
\textbf{Cost}: exact token counts of every prompt/response pair, priced at a representative frontier tier (\$3/\$15 per Mtok in/out; Claude Sonnet standard pricing, July 2026) with cache pricing as above, reported as tokens, USD per submission, and USD per assignment, following the per-bug cost accounting of ChatRepair \citep{chatrepair2024}.
Repair rates carry 95\% Wilson intervals; paired comparisons use exact McNemar tests.

\subsection{Protocol}
All LLM interactions---\NumEval{} baseline repairs and every builder/refinement call---are single-shot prompt$\to$response exchanges executed by the same frontier model (Claude, July 2026 snapshot) under identical instructions, with no code execution or test access at generation time; all validation is performed by our harness.
Local search is deterministic; LLM calls are single-sample ($n{=}1$), matching the deployment setting of one repair attempt per submission.
Costs are computed from the exact message strings with a fixed tokenizer approximation applied identically to all arms (chars/3.6; provider tokenizers are unavailable offline); because the arms differ in input/output mix, we release every raw string for exact re-tokenization and note that a $\pm$20\% differential calibration error shifts break-even points by at most the same factor.
To probe sensitivity to builder capability, we additionally re-ran the entire synthesis pipeline with the Haiku-tier model as the builder (same prompts, same $R_{\max}$).
Experiments ran on a single Linux container (no GPU); synthesized repairers used a 60s timeout and $\tau{=}0.35$ throughout.

Table~\ref{tab:main} presents the headline comparison.
The per-submission frontier-LLM baseline repairs \BaseRate\% of submissions---consistent with the near-saturated rates modern LLMs achieve on introductory assignments \citep{pydex2024}---which makes it a demanding reference point: the question this paper poses is not whether LLMs can repair student code, but what each repair needs to cost.
\textsc{CoEP}'s synthesized repairers alone fix \CoepRate\% (CI [68.0, 80.6]) at zero marginal LLM cost---with median latency 0.05\,s per submission on one CPU core (mean 2.5\,s, dominated by \texttt{gcd}'s search; one 60\,s timeout)---and with fallback the hybrid reaches \HybridRate\%, matching the baseline by construction.
The local path is also \emph{safe}: across all \NumEval{} attempts it produced zero test-failing and zero over-cap patches; its only failure mode is abstention ($\bot$), never a wrong repair.

Patch quality is preserved, and its \emph{guarantee} changes character.
The baseline model may rewrite freely, and does: 7.3\% of its test-passing ``repairs'' (13/179) exceed the RPS cap, discarding the student's approach---the failure mode \citet{itsp2017} identified as pedagogically useless.
\textsc{CoEP} cannot produce such a patch: cap compliance is checked mechanically on every candidate.
A paired view shows there is no hidden quality tax: on the 134 submissions \textsc{CoEP} repairs locally, its patches are as minimal as the baseline's on the same instances (mean RPS 0.058 for both, paired); the baseline's heavier aggregate tail (mean \BaseMeanRPS) is driven by its 13 rewrites, \emph{all} of which strike misconception-crafted bugs---exactly the pedagogically sensitive cases---and all of which fall on submissions \textsc{CoEP} escalates anyway, so the hybrid's quality profile (\BaseQualityRate\% cap-compliant) equals the baseline's.
What changes is enforcement: minimality and determinism hold for local repairs \emph{by construction}---a prompt can request these properties, but only a validator can guarantee them.

Per-assignment rates (Figure~\ref{fig:perproblem}) range from 50\% (\texttt{balanced\_brackets}, whose stack-discipline bugs often need multi-edit structural fixes) to 95\% (\texttt{grade\_stats}).
The dispersion tracks how far an assignment's misconceptions lie from small-edit repairs---a property instructors can estimate in advance, and a natural signal for routing hard assignments to a larger build budget.

\subsection{RQ3: Where Does the Power Come From?}

\textbf{Synthesized rules vs.\ generic search.}
The generic-only ablation---the same operator library and validation, with no LLM-synthesized rules---repairs \AblRate\% overall, but the aggregate hides the mechanism.
On mutation-generated bugs both variants fix 94/99 (95\%): mutants lie inside the generic operator space by construction, so inverting them requires no assignment understanding.
On misconception-crafted bugs the generic search collapses to 17/80 (21\%) while full \textsc{CoEP} reaches 40/80 (50\%)---the synthesized rules \emph{more than double} repair rate exactly where bugs stop being single-token slips (exact McNemar, discordant $23{:}0$, $p{=}2.4\times10^{-7}$).
Qualitatively, the rules that fire on crafted bugs are structural: inserting a missing \texttt{else} branch, wrapping a loop body in a recursive call, replacing order-destroying \texttt{set()} deduplication with an adjacency comparison---edits no generic mutation operator produces.
This is the paradigm's core claim made measurable: what the builder amortizes is assignment-specific \emph{understanding}, not search.

\textbf{Refinement rounds.}
Seven of ten builders produced a repairer that fixed all five build samples in a single shot; three did not (two returned no patches at all due to internal defects, one missed structural cases).
Feedback rounds repaired the builders themselves: round~2 fixed \texttt{is\_palindrome} outright ($0/5 \to 5/5$; its eventual held-out rate, 70\%, is indistinguishable from single-shot builders), and rounds 2--3 lifted \texttt{flatten} and \texttt{unique\_in\_order} from $0$--$3/5$ to $4/5$.
Overall build-sample success rose from $38/50$ (round 1) to $48/50$ (final)---evidence that the validate-and-refine loop, not single-shot generation luck, makes synthesis reliable; feedback that includes the still-failing submissions was what unlocked the two hardest builders.
An independent replication of the entire frontier-builder pipeline (fresh samples, same prompts and $R_{\max}$) confirms this mechanism: single-shot success varied substantially ($27/50$ vs.\ $38/50$), yet refinement converged both replications to $48/50$ build success and statistically indistinguishable held-out repair (72.6\% vs.\ 74.9\%, both inside the CI)---the loop absorbs synthesis variance.

\textbf{Builder capability.}
Re-running the entire synthesis pipeline with the Haiku-tier model as builder (same prompts, same $R_{\max}{=}3$) yields repairers that fix 51.4\% of held-out submissions (92/179)---above the generic-only floor (62.0\% pooled, but only 21\% on crafted bugs, vs.\ 31\% for the cheap builder's rules) yet well below the frontier builder's 74.9\%; two of its ten repairers never became usable within three rounds.
The cheap builder's build cost (\$0.011/assignment) is recouped after ${\approx}$7 submissions, and upgrading from the cheap to the frontier builder pays for its extra \$0.115 within ${\approx}$164 submissions.
Synthesis quality is thus a capability-sensitive investment with a rational upgrade path---and since building is a one-off cost, the frontier builder is the right default at any realistic scale.

\section{Discussion and Limitations}
\label{sec:limitations}

\textbf{Construct validity.}
Repair rate is measured against visible tests, as in prior assignment-repair work \citep{refactory2019,pydex2024}; a patch could overfit the suite, and \textsc{CoEP}'s search optimizes that oracle directly.
Two design choices bound this risk: suites include adversarial edge cases (14 tests per assignment), and the RPS cap prevents the degenerate overfit of wholesale replacement---a failure mode we in fact observe in the \emph{baseline}, 7.3\% of whose ``repairs'' exceed the cap, while the local path produced zero.
The frontier baseline's 100\% repair rate is a ceiling: on CS1-scale programs, modern LLMs saturate functional repair \citep{pydex2024}, which is precisely why our comparisons are designed around cost and quality at parity rather than repair-rate deltas; benchmarks that separate frontier models on repair rate (larger, multi-function assignments) are where the paradigm question should be re-asked next.
Our cost model prices one provider tier; because we report raw token counts, any pricing can be substituted, and the break-even expression in RQ2 is closed-form in the price.

\textbf{Internal validity.}
Both paradigms use the same model, the same single-attempt budget, and the same independent validation harness, and the builder never sees evaluation bugs.
Two circularities deserve explicit statement.
First, the mutation half of the benchmark is generated by the same operator implementation the generic search inverts; we therefore treat mutants as calibration (both local variants solve $\approx$95\%) and rest every claim about assignment understanding on the crafted pool, reporting crafted-only economics alongside pooled ones.
Second, the crafted bugs were authored by LLM agents of the same model family that powers both repair arms; authorship bias, if any, favors the \emph{per-submission baseline} (an in-distribution generator--solver pair), not the symbolic repairers whose rules must survive an independent validator---but only evaluation on real student corpora, which we could not use without contamination, removes this threat entirely.
The LLM calls were executed through an agent harness constrained to behave as a stateless single-shot endpoint (no tool use, no test execution); reported costs are computed from the exact message payloads.
Token counts use a fixed approximate tokenizer applied to both arms; ratios and break-even points are therefore unaffected by calibration error, and we release all raw strings for exact re-tokenization.

\textbf{External validity.}
Our benchmark is synthetic-but-principled---the price of a memorization-safe comparison.
Real distributions are heavier-tailed: more near-duplicates (which \emph{favor} amortization) but messier failure modes that will raise the fallback fraction $f$; the hybrid degrades gracefully there, and the break-even analysis is explicit in $f$.
We evaluate one language, one model family (two tiers), and CS1-scale assignments; multi-function projects are open.
The economics assume assignments recur at scale---the regime of public corpora ($\approx$340 buggy submissions per assignment in Refactory \citep{refactory2019}) and of MOOCs.

\section{Related Work}
\label{sec:related}

\textbf{APR for programming assignments.}
Pre-LLM systems exploit per-assignment structure---CLARA's clustering \citep{clara2018}, Sarfgen's aligned-example search \citep{sarfgen2018}, Refactory's refactoring-based repair \citep{refactory2019}, Verifix's verified alignment \citep{verifix2022}---and \citet{itsp2017} established test-based repair rates and the feedback-suitability concern behind patch-size metrics; all are cheap per submission but need many prior correct solutions or hand-built machinery.
At AAAI, the setting remains active from the per-submission side: counterexample-guided repair \citep{orvalho2025} and minimal-modification adaptive repair \citep{adapr2025}.
\textsc{CoEP} keeps the classical per-assignment amortization but replaces the machinery with LLM synthesis from a handful of examples.

\textbf{LLM-based repair.}
AlphaRepair and successors recast repair as generation \citep{alpharepair2022}; ChatRepair adds conversational test feedback and per-bug cost accounting \citep{chatrepair2024}; PyDex/MMAPR target student programs \citep{pydex2024,mmapr2022}; FastFixer accelerates per-query inference \citep{fastfixer2024}; CREF adds tutor-in-the-loop conversation \citep{cref2024}.
All are per-submission; \textsc{CoEP} is complementary---any can serve as its fallback---but shifts the primary cost to the assignment.

\textbf{Template- and pattern-based APR.}
PAR and TBar showed that a fixed library of human-curated fix templates repairs a surprising share of real bugs \citep{par2013,tbar2019}.
\textsc{CoEP}'s generic operator layer is a mutation-inversion instance of this idea \citep{mutants2014}; its novelty is the \emph{synthesized, assignment-specific} template layer, authored per specification by an LLM rather than curated once globally by humans.

\textbf{Cost-efficient LLM inference.}
FrugalGPT's cascades route queries between models of different prices \citep{frugalgpt2024}; SRepair engineers cheap open-model pipelines (\$0.029/bug) \citep{srepair2024}; provider prompt caching discounts repeated prefixes \citep{anthropiccaching,openaicaching}.
All optimize \emph{within} the pay-per-query paradigm and are composable with \textsc{CoEP} (our cached baseline; a cheaper fallback model).
\textsc{CoEP} instead removes queries: the majority of submissions never reach a model.

\textbf{LLMs synthesizing reusable tools.}
Voyager's skill library and LLMs-as-tool-makers show agents that write reusable code artifacts amortized across future episodes \citep{voyager2024,toolmakers2024}, and self-refinement loops improve one-shot generations \citep{selfrefine2023,reflexion2023}.
\textsc{CoEP} carries this idea into APR with two twists that the education setting forces: the synthesized tool must be \emph{verifiable} (test-suite validation, never-trust-self-reports) and \emph{quality-constrained} (RPS cap), because its output is feedback to a learner.

\section{Conclusion}
Programming-assignment repair has a structure that per-submission LLM querying ignores and per-assignment synthesis exploits: one specification, many failures, recurring misconceptions.
\textsc{CoEP} turns cents of frontier-model reasoning into a permanent, local, verifiable repairer per assignment---matching the per-submission paradigm's repair rate and patch quality at 4--10$\times$ lower marginal cost depending on the fallback stack---and it breaks even against even the strongest zero-build alternatives inside a single course offering.
Per-assignment synthesis is one instance of a broader recipe---\emph{amortize LLM reasoning into verifiable executable artifacts wherever many instances share a specification}---that applies to grading rubrics, hint generation, and beyond.

\section*{Ethical Statement}
\textsc{CoEP} automates feedback, not grading, and should deploy under instructor oversight.
\emph{Fairness}: a repairer's rules reflect its sample bugs, but students whose approaches it cannot handle receive full-LLM treatment---never degraded service---and local repair is deterministic and auditable.
\emph{Learning displacement}: the RPS cap keeps output as minimal, explainable edits, and deployments can surface failing tests before patches.
The benchmark contains no student data, avoiding consent and privacy issues.
